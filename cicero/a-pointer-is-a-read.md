# A pointer is a read

**Status: Decided 2026-10-03, Executed 2026-10-03.** A design round with Egildo, 2026-10-02 and 2026-10-03, on a survey of the published text, the pinned Chromium, the four rival clones and two real documents (the survey's numbers are in the Measured section). The record names a shape; the round that built its first three reads, `cicero/the-reads-are-built`, executed it the same day, and what that round decided beyond this record, what it measured and the verdict on the five predictions are in *Built* and *Verdict* below. **The word is Egildo's, ruled 2026-10-03: a read, the tablet's own word (C9, "every ledger read"), and not a slot.** In this engine a slot is the Chase's `<slot>`, the mechanism that hosts a node; the two words meet at exactly one row, a read whose fact is a node is delivered through a slot, and nowhere else.

## Context

A real document's contents page printed no page numbers and no leaders under this engine. The shell writes `.toc-entry a::after { content: target-counter(attr(href url), page) }`; Chromium keeps the declaration in the CSSOM and fails it at computed-value time, so the pseudo-element computes `content: none` and generates no box, and the addendum's `justify-content: space-between` then throws each title to the far right. The checklist entry read "designed (reservation policy open, part two)" and the architecture names the hole in as many words: the Cast-off's `reserve` is "a declared hole: the interface stands, the policy is undesigned".

Before designing the policy the round asked what else points somewhere in a document, because `target-counter()` is not alone and a mechanism built for it alone would be the fourth of its kind. The belt's `ref-text` plugin stamps a cross-reference's target text as `data-ref-text`; the site engine fills `:ref` from a computed ordinal in `data-ref`; the shell writes `target-counter()` for the paged engines; this engine's `document-state.js` resolves `string()` and author counters for a margin box; and footnotes are a pointer the belt writes as two elements and `inlineFootnotes` folds back into one. Five mechanisms, each knowing one moment of one kind of edge.

## What the text says

- css-content-3 (an Editor's Draft that calls itself "a very rough draft, and is not ready for implementation") §2.6: `target-counter()` "retrieves the value of the innermost counter with a given name. The required arguments are the url of the target and the name of the counter"; `target-text()` "retrieves the text value of the element referred to by the URL"; "These functions only take a fragment URL which points to a location in the current document. If there's no fragment, if the ID referenced isn't there, or if the URL points to an outside document, the user agent must treat that as an error." Nothing on when the value is computed, on a value that depends on the layout it changes, or on what the error does.
- css-gcpm-3 §1.1.2: `string()` "is used to copy the value of a named string to the document, via the content property", with no restriction to margin boxes; §1.2.3: `element()` "places an element … in a page margin box".
- css-gcpm-3 §2.5.2: the footnote counter "should depend on the position of the footnote element in the document tree, not where it is eventually placed. A footnote element may sometimes be placed on the page after the footnote call, but the same counter value must be used for both." §2.8: "A footnote body must never be placed on a page before the footnote reference."
- css-page-3 §6.1: "A counter named page is automatically created and incremented by 1 on every page of the document."
- The tablet, C9: "Every ledger read decomposes into a geometric footprint, settled before its entry is written, and a symbolic value, delivered afterward as a literal. A footprint that cannot be reserved stably turns its resolution into late-arriving truth." And: "a footprint that is a function of the cut is circular by construction … That is why the footnote needs a solver and the float does not."

## Decision

**A pointer is a read, and every read has the same six parts.** Two kinds of node exist: the document's elements, and the pages, which exist only at layout. A read is a site that shows a fact about another node.

- **Site**: where the value appears. A pseudo-element in the flow, a margin box, a footnote call.
- **Address**: how the other node is named. **By id**, one element (`target-counter()`, `target-text()`, `:ref`, the footnote pair); **by name**, a position-ordered log of assignments (`string-set` for `string()`, `running()` for `element()`); or **the page itself** (`counter(page)`, `pages`).
- **Fact**: what is shown. Text, a number, or a hosted node (`element()` delivers the running element, the footnote delivers its body). A hosted node is delivered through a slot, the Chase's own, and may carry reads of its own, a running head with a counter, a footnote with a cross-reference inside; the shape must allow that or the running head's counter is a special case forever.
- **Moment**: when the fact is settled. **Written** (text), **cascade** (counters and named strings, one walk of the tree before the run), **layout** (anything about pages). The moment belongs to the edge, not to the function name: `@page { counter-reset: footnote }` turns a footnote call's number from a cascade fact into a layout fact, how many footnotes this page holds before me.
- **Footprint**, and where it is charged. **None** (chrome, fixed tracks); **at the site** (a word in the line); **on the page** (the footnote body, which shrinks the area the cut is decided in).
- **Direction** relative to the flow. **Backward**, already known when the site is reached; **local**, the page the site itself stands on (`string(x, last)`, the footnote's cut against its area); **forward**, a layout fact of an element not yet reached (a contents page's numbers).

**Layout facts are never stored. They are reads of the ledger's assignment of elements to pages**, one relation read in four directions: which page holds this element (`target-counter(page)`, the footnote body); which elements does this page hold, in order (`string()`, `element()`); which page am I (`counter(page)`); how many pages (`pages`). The ledger owns the relation and already has its verb, `root.pageOf`. The graph of a document records only the static edges, the id edges and the name logs, both settled by the cascade; the page enters as a filter on either.

**`leader()` is a read of its own line, and it is wanted, not built.** It is not a pointer: there is no other element. css-content-3 §2.5.2 says the leader string "must appear in full at least once", "should be as long as possible", "only appears on a single line" and "can't be the only thing on a line", so what it shows is how much room its own line has left between what stands before and what stands after. That adds a third node to the two above, the **line**, and makes three scales of *the fragment the site stands in*: the line for `leader()`, the page for `counter(page)` and the footnote's solver, the document for `pages`. The rest of the shape fits without bending: the moment is layout at line scale, the direction is local, and the footprint is at the site with a reservation that is exact rather than guessed, one full copy, the text's own minimum; the fill afterwards only takes slack, so by construction it cannot move a line. It is filled last, because it depends on the other reads in its line (the text's own contents example is `leader('.') target-counter(attr(href url), page, lower-roman)`), and it is filled by the oracle, as the tablet says ("generated decision-side with oracle-measured fill"): deliver n copies, let the browser say whether the block grew, search on n, batched across every site. **Its open part is the address of the site**: the fill differs per site, so the delivery rule must reach one element with nothing written on it; beside a `target-*` the `href` serves, alone it needs a structural address, and originals and continuation clones do not share one. No document met so far writes `leader()` — the venue draws its dots as the `::after`'s own border, the addendum uses `space-between`, and both work again the moment the `::after` has a box — Chromium drops a bare `leader()` at parse, Paged.js and pagedNG do not implement it, and WeasyPrint does (`layout/leader.py`, filled after line layout).

**Reservation and the check after delivery exist for forward layout facts whose footprint is in the flow, and for nothing else.** A written or cascade fact is known before the run and is delivered as its true value from the start. A chrome read has no footprint and is delivered after the run, which `pages` already does. The footnote never looks forward and its loop is local, solved at the cut. What remains is `target-counter(page)` to a later element and, the day this engine reads `string()` in the flow, `string(x, last)` on its own page. For those: a reservation stands in the line during the run, the true value is delivered afterwards, the blocks holding such reads are re-measured, and only a block whose lines moved sends the run again with the delivered values standing. Budget three runs; the build cannot fail, so on exhaustion the last values stand and the console names the references that still moved. The reservation is **`0`**, Egildo's ruling of 2026-10-03: it is wrong for nearly every reference (32 of 39 in the venue's contents, 188 of 191 in the manual's), so nothing rests on it and everything rests on the check, which is cheap; it needs no page estimate, so the Cast-off's `reserve` stays unbuilt; and it must never be printed, which the budget's fallback guarantees by keeping the last true values rather than the zero. The rivals' alternative, a `0` that stays when a run does not settle, was refused: a printed `0` reads as a page number.

**Delivery writes nothing on the author's elements.** The host rewrite (`seam/rewrite.js`, the mechanism that already carries `string-set`) rewrites the function in place inside the author's own declaration, so the author's cascade still decides which rule wins, into a read of a custom property reserved to this engine and defaulting to the reservation. The values arrive in a constructed sheet the engine adopts, one declaration per distinct target, keyed by the very attribute the function reads: `a:where([href="#x"])::after { --beltype-read-<rule>: "47" }`. A custom property set this way reaches originals and clones alike, moves no specificity on `content`, and needs no `!important`; the counter style is spelled by `src/counter-styles.js` before delivery, so numbers and text travel the same way. A missing target leaves the property unset: the read's fallback is an empty string, so the box exists and the leader still draws, and the console names the link once. Measured cost of the keyed rules in the pinned Chromium: 1.1 ms for 100, 11 ms for 500, 37 ms for 1 000; the venue has 39 references and the manual 191.

**The shell's spelling is not changed in this round.** It writes `attr(href url)`, a typed form the current css-values-5 draft forbids ("`<url>` is banned because, for now, `attr()` values can't be used in URLs at all"); the engine reads whatever text the CSSOM holds and parses the function itself, so the spelling is the shell's business and is filed, not fixed here.

**Where the graph lives.** The engine's reference table built for this round is the first instance of the shape: site, address, fact, moment, footprint, direction, value. It is not yet seated in the resolved document's spine. Four readers would read one table there: this engine delivers the page, the site engine delivers the ordinal (since 2026-10-19 the site delivers every read but a page's with this engine's own `findSites`, `staticValues` and `deliver`, borrowed at run time, so the site is the second reader of the static half; *the site reads*, `.claude/plans/the-site-reads/plan.md`), the editing tools follow an edge both ways and the inspector says which rule at which line made which number from which target, and Caster writes PDF link annotations, which need exactly the target's page. The table moves into the spine when the second reader arrives, not before; and the belt cannot see a pointer an author writes only in CSS (the venue's own `a.internalref::after { content: ' (pag. ' target-counter(attr(href), page) ') ' }`), so the engine always adds those sites to whatever the belt lists.

**The ordinary name.** A spreadsheet: a cell shows a fact about other cells, recalculation walks the dependency graph, and a circular reference gets iterative calculation with a pass budget and a convergence test. The rim the architecture describes, `ledger.voidFrom` and rebuild forward, is that recalculation, and this table is the dependency graph it has been waiting for.

## What the rivals do

Read in the clones; the survey ran WeasyPrint and Paged.js on the venue's document.

- **Paged.js classic** (`src/modules/generated-content/target-counters.js`): rewrites the declaration to `counter(target-counter-<uuid>)`, stamps a `data-target-counter-<uuid>` attribute on the author's element once the target's page is laid out, and inserts a `counter-reset` rule for it. The stand-in is an unreset counter, `0`. It never re-cuts: a wider number reflows inside an already-cut page. **Measured 2026-10-03** (case 82's README): that reflow is not harmless — on case 82 the wrap the two-digit number makes pushes a line out of page one's area, and its two words, `f1w012` and `f1w013`, are on no page of the PDF. It resolves `page` from the page boxes and only those author counters the target element itself increments. No `leader()`, no `target-counters()`.
- **pagedNG** (`src/handlers/target-counters.js`, the pass loop in fragmentainers' `fragmenter.js`): rewrites to `counter(--paged-tc-N)`, stamps an inline `counter-reset` on the referencing element each pass, stand-in `0`, re-lays out from the earliest invalidated fragmentainer, budget `PASSES = 3`, and throws `LayoutPassLimitError` when the budget is exhausted ("an unsettled document is a bug, not a degraded rendering"). Author counters from a tree walk, so ancestor resets count. `leader()` out of scope.
- **WeasyPrint** (`css/targets.py`, `layout/__init__.py`): a `TargetCollector` of pending references with `parse_again` callbacks, the box's text rebuilt when the target is known, nothing written on the source; page counters cached as pages are made, stand-in `0`; `layout_document(max_loops=8)` remakes only the pages flagged `content_changed`, and stops silently when the loops run out. A missing target logs an error and the content is dropped. `leader()` implemented. **Corrected 2026-10-03 by measurement** (case 82's README): WeasyPrint 70 cuts case 82's eleven-page fixed point and prints `10` for the entry whose target stands on page eleven, so its loop can stop well inside its budget with a value its own layout contradicts — not only when the loops run out. Why is inferred from `layout_document`'s `content_changed` test and not run.
- **fragmentainers** has no handler of its own; it supplies the pass loop, `locate` and the pass-limit error pagedNG uses.

Taken: the rewrite-in-place so the author's cascade stands (all three), the pass budget of three with convergence on unchanged values (pagedNG), delivery that writes nothing on the source (WeasyPrint). Refused: the attribute stamp and the inline `counter-reset` (a write on the author's element), the thrown error at the budget (the build cannot fail), the silent stop with a `0` standing (a printed `0` reads as a page number), and `0` as the answer for a missing target.

## Measured

The survey of 2026-10-02, pinned Chromium 153.0.8010.12, both documents served read-only from their venues.

- The venue's contents: 39 entries over two pages, numbers 7 one-digit, 20 two-digit, 12 three-digit, highest 123; the face's ten digits all advance 7.469 px (tabular). The manual's: 191 entries, 3, 42 and 146, highest 276; Source Serif 4's digits all advance 7.406 px.
- Replacing the number with `"4"`, `"44"`, `"444"` or `"4444"` moved no line break and no entry height in either document. What moved them was the box existing at all: 16 px to 17 px on 37 venue entries (the dotted border), and one two-line entry's first line ending after 88 characters instead of 95. The tightest one-line entry has 57.5 px of slack against a three-digit number's 22.4 px.
- Chromium keeps every `attr()`-bearing form of the declaration in the CSSOM and computes `none`; it drops `target-counter("#t", page)` with a literal URL and a bare `leader()` at parse, and a custom property carries either verbatim. `CSS.supports('content', 'target-counter(attr(href url), page)')` is true.
- A keyed rule setting a value on the pseudo-element applies to the venue's presented originals in `beltype-root`'s light DOM and generates the box with the author's `flex-grow`, `text-align` and dotted `border-bottom` intact.
- Cicero paginates the venue in 654 ms and the manual in 3 895 ms; a second full run on a block whose lines moved costs that again, which is why the check re-measures the referencing blocks first and re-runs only on a moved block.

1. The venue's contents page under this engine shows the same 39 numbers Paged.js shows, at the same digit widths, with the leader drawn, after one run and no re-run: no referencing block's lines move when `0` becomes the true value. ## Consequences

- **The first round builds three reads on this shape**: `target-counter(page)`, the only forward layout fact; `target-counter(<author counter>)`, a cascade fact answered by `document-state.js` with one variant of `counterStateAt` that reads the counter after the target's own operations rather than strictly before; and `target-text()`, a written fact, the cheapest of all and the one the belt already stamps, so the record can name the collapse with a live example. `target-counters()` and `leader()` stay wanted: the first needs nested counter values the walk does not keep, the second is the read of a line described above, with the address of its site open.
- **The checklist's GCPM entry** moves from "designed (reservation policy open, part two)" to decided, pointing here, and gains the limits above. **The architecture's design-opens list** loses "the C9 reservation policy" and gains the shape of a read; the Cast-off interface's `reserve` is marked as not needed by this policy.
- **A tension with the tablet, stated and not edited.** The tablet writes "Cross-page targets — target counters, target text — are C9 lived: footprint reserved in the line at measure time, value resolved once the target's entry exists". Under this record `target-text()` is a written fact and reserves nothing, and a `target-counter()` of an author counter is a cascade fact and reserves nothing either; only the page counter is C9 lived. The tablet changes in a design round with Egildo, and that sentence is quoted here for him to rule on; until he does, the tablet stands and this record is the narrower reading.
- **Left standing, on purpose**: `string()` in the flow (the text allows it, the engine reads it only in margin boxes; when it comes it is a local read with a footprint and the same check); a `0`-free spelling for roman and alphabetic styles (a `0` formats as `0` in every style; irrelevant under the check); the shell's `attr(href url)`; Caster's reach to a delivered literal through the computed `content` (inferred from `reify.js`, not measured, and nothing prints Cicero through Caster yet); the seat of the table in the spine and its three other readers.
- **What this does not touch**: the Gauge, the Stonehand, the driver's cut, the positions. Delivery is presentation and a re-run is the whole run again; no rim is built here, and `voidFrom` keeps its unit test and no caller until a round builds the rim on this table.

## Built

**Where it lives.** `seam/rewrite.js` — the one implementation the seam's client, the essay's client and the editing tools' dresser all call, so all three got the branch by construction — replaces each `target-counter()` and `target-text()` in an element's `content` by `var(--beltype-read-…, "")`, in place, the value's other terms and the declaration's `!important` untouched: `a.internalref::after { content: ' (pag. ' target-counter(attr(href), page) ') ' }` becomes `content: ' (pag. ' var(--beltype-read-counter-attr-href-page-decimal, "") ') '`. It reads the four spellings this record names — `attr(href url)`, `attr(href)`, a string and `url()` — and the optional counter style; `target-counters()` and a function in a margin at-rule are left as written. `src/reads.js` is the engine's half: it finds the sites in the CSSOM, computes the values, delivers them, and holds the loop; `driver.js`'s `paginate()` is now `settleReads` around one whole run (`paginateOnce`, the old body unchanged), which is the one door every host enters by. `document-state.js` gained `marks` and `counterStatesAfter`; `positions.js` gained `pageContaining`; `gcpm-encoding.js` gained the read's name, `encodeRead`/`decodeRead`, and `parseReadFunction`.

**One real delivery**, from case 79's run: the rewritten declaration is `a::after { content: " " var(--beltype-read-counter-attr-href-page-decimal, ""); }`, and the sheet the engine adopts holds, among five such rules, `:where([href="#s4"])::before, :where([href="#s4"])::after { --beltype-read-counter-attr-href-page-decimal: "3"; }`. No rule is written for `#nowhere`, so that entry's fallback `""` stands and its box exists empty.

**Decided in the build, for the coordinator to confirm** (2026-10-03):

1. **The property's name is the read's meaning, not a rule's number.** The record's example names a property per rule (`--beltype-read-<rule>`). Built, the name spells the function, the address (an attribute's name or a literal URL), and the counter and its style or the text's keyword — `--beltype-read-counter-attr-href-page-decimal`, every character outside `[A-Za-z0-9]` written `_<hex>_` — so the engine learns what a property means from the rewritten sheet alone, in the style the `:blank` page name already uses, and nothing travels beside the sheet from the host that rewrote it. **When two rules read the same target**, they read the same property if they write the same function, and get one declaration; if they write different functions (a figure's number and its page), they get two declarations in the one rule that target has. One rule per distinct target either way.
2. **The fallback is `""` and the reservation is delivered.** The record says both "defaulting to the reservation" and "the read's fallback is an empty string"; one `var()` has one fallback. Built, the fallback is `""` — what a missing target shows — and the `"0"` of the first run is delivered explicitly for every page read whose target exists.
3. **The declaration lands on the pseudo-elements, not on the element.** `:where([href="#x"])::before, :where([href="#x"])::after`, unregistered: a custom property set on the element would inherit into every descendant, so a nested link with no target of its own would show its ancestor's number. Nothing is registered, so nothing outlives the sheet.
4. **A site is every element a read's rule matches with the pseudo-element taken off its selector.** Whether a later rule overrides its `content` is the browser's cascade; a value delivered to an element that never reads it is one declaration that shows nothing. Grouping rules and imported sheets are walked; a nested style rule is not, a stated limit.
5. **The page of a target is the page whose interval holds its first word, by the arithmetic alone** (`pageContaining`). `root.pageOf`'s refusals are block-wide, and a top-level block in a BelType document is a whole chapter: under them, 19 of the manual's 191 contents entries showed nothing (measured on the first build, then changed). Two stated limits come with the arithmetic: a target with no word of its own lands where the next word does, and a word inside a box sliced at the page edge reads the last slice's page. A target outside the flow — inside a running element or a fixed box — has no page and is named on the console.
6. **A line "moved" is the Gauge's own reading of the box the site stands in**: its height and the line of every word, read on a clone of the site's top-level block at the content width of the page the site is on, once with the values the run was laid out with and once with the true ones. Only sites whose value changed are measured. A run is "converged" when the values it produced are the values it was laid out with.
7. **On exhaustion the true values of the third run stand**, on the third run's layout, and the console names the references whose lines they still move.
8. **The written and cascade facts cost a second walk** of the document's counters, `documentOpsOf` over a fresh position index, and only where a document has a counter read; the run's own walk is not reused, so the run stays untouched.
9. **`target-text()`'s `before`, `after` and `first-letter` are read as `content`**, the same stated limit `string-set`'s `content()` has.
10. **The composed mode refuses a paragraph whose lines carry generated text** — its own record, [*the composition refuses generated text*](the-composition-refuses-generated-text.md), because it is a line-breaking decision and not a delivery one.

**Audited.** Every caller of `paginate()` — the seam's `run()`, the essay's `run()` and `view()`, `seeds/benchmark.js`, and the four probes that call it directly (`margins`, `rungs`, `forcing`, `impossible`); the probes rewrite nothing, find no read and run once, as before. Every caller of `rewriteSheet` — `rewrite-document.js` for the two clients and the editing tools' `app.js` for the dresser — takes the new branch with no change; `rewriteDocumentSheets`'s tally gained `reads`. `pageOfPos` is unchanged and still answers `pageOf`. The one assertion outside this package that moved is the editing tools' acceptance test, which counts the sheets adopted in the dressed Cicero pane: its specimen has a contents page, so the delivery sheet is one more, and the test now counts it by name. Nothing is written on an author's element: a probe over the manual's presented pages finds no `--beltype` inline style and no `data-target-counter` anywhere.

**Measured**, pinned Chromium, one machine, the manual served by `node bin/beltype.js ./docs/index.md --engine cicero` and read by a scratch Playwright script launched as the essay launches Chromium, three runs each way:

- **The manual**: 271 pages. Before the round 3 831, 3 933 and 3 846 ms (no number shown); after, 4 046, 4 092 and 4 048 ms, **one run**, all 191 contents numbers shown — 4 of one digit, 42 of two, 145 of three — and each equal to the page its heading is presented on, read independently off the slot the heading's presented box is assigned to; all 191 entries stand in continuation fragments, so the delivery reaches clones. Of the ~200 ms the reads add, 113–125 ms is finding the sites and the counter walk for the manual's one cross-reference, and 37–40 ms is the check after delivery; a run itself (`paginateOnce`) is about 2.6 s. In the composed mode, 275 pages in 8.2 s, one run, all 191 equal.
- **Case 82**: two runs in both modes, 1, 4, 9 and 11, eleven pages. **Case 79**: one run, five numbers and an empty box, the console naming `<a href="#nowhere">`. **Case 80** and **case 81** deliver everything before the first run.
- **The case suite**, `node cases/runner.js`, the whole of it before and after: 1 155 `ok` and 14 `FAIL` before, 1 169 `ok` and none after; the fourteen lines that changed are the fourteen failures of cases 79 to 82, and no other line moved.

**Left standing**: everything the Consequences above leave standing, and the build's own limits — a nested style rule's read is not found; a target with no word lands with the next word; a word inside a box sliced at the page edge reads the last slice; a target the counter walk does not reach (inside `display: none` or a fixed box) shows nothing and is named; the console line for a missing target is not something a case can assert.

## Verdict

1. **The venue's contents in one run** — the coordinator's, after this report: the venue is outside the repository and this round did not go there.
2. **The manual's contents settle in one run — HELD.** One run in both modes, 191 numbers, each the page its heading is presented on. The check after delivery measured the 191 changed sites and found no line moved.
3. **A constructed entry wraps on delivery and settles on the second run — HELD.** Case 82, read off the run's own `cicero:adjudicate` measures and its delivery sheet: the first run, with `0` standing, adjudicated ten pages; delivering `10` moved the fourth entry's line; the second run, with `10` standing, adjudicated eleven and produced `11`, which moved nothing, and the sheet left adopted holds 1, 4, 9 and 11. Two runs, never three, in both modes — the composed mode only once the composition refused generated text.
4. **`target-text()` on `.xref` prints what the belt stamps — HELD, on the one reference the manual has.** With a scratch rule `.xref::after { content: target-text(attr(href url)) }` added before the run, the manual's one `.xref` printed `The annual migration`, its `data-ref-text` exactly, in one run with no reservation. One of one is the whole population and a thin one.
5. **Every standing battery record unmoved — premise BROKEN, the record the coordinator's.** "No case in the corpus writes a `target-*` function" is false: case 26 writes `content: leader('.') target-counter(attr(href url), page)`. Chromium drops that declaration at parse, for its `leader()`; after the rewrite it parses and fails at computed-value time instead, for the same `leader()`, so it still computes `none` and case 26 printed exactly what it printed before — the whole case suite moved no line outside cases 79 to 82. ## Amended 2026-10-14 — two limits taken off *Left standing*

The round *counters and reads* built both. **A read inside a nested style rule is found** (case 106): `seam/rewrite.js` parses again, at its own offset, line and column, the raw text css-tree 3.2.1 leaves for a nested rule that does not open with `&` (its `Block` parser reads a nested rule as a rule only then, and a bare `a::after { … }` becomes a declaration whose raw value swallows the rest of the statement, a plain declaration after the nested rule included), and walks the fragment with the same visitor, so every edit still lands on the author's own text; `findSites` visits a style rule's `cssRules` and resolves a nested selector by replacing each `&` with `:is(<the parent's resolved selector>)` (a selector with no `&` is a descendant of the parent; a `CSSNestedDeclarations` rule takes its parent's selector; a `&` inside a string or an attribute value is a stated limit). Item 4 above ("a nested style rule is not walked") is therefore history. **`target-counters()` is read** (case 107): `target-counters(<address>, <name>, <string>[, <style>])` is parsed, the separator rides the encoded name as a field, and delivery joins `counterValues(state, name)` formatted in the style, from the counters AFTER the target's own operations; the reason this record gave for *stays wanted* — nested counter values the walk does not keep — had stopped being true when `counterStateAt` returned every instance in scope.
