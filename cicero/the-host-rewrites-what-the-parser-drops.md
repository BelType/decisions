# The host rewrites what the parser drops

**Status: Decided 2026-09-14, Executed 2026-09-14.** Ruled in the design round with Egildo that opened the scenarios brief's second decision.

## Context

The capture reads the browser's own parsed page rules and nothing else — [*a page rule reads its own declarations*](a-page-rule-reads-its-own-declarations.md) — and that ruling is right for everything the browser parses. Four things it refuses at parse, measured 2026-09-14 in Chromium 150 through `packages/browser-chromium`: `string-set` on an element, `position: running()` on an element, `content: string()` and `content: element()` in a margin at-rule, and the whole of any `@page` rule whose selector carries `:blank`, a selector list, or an unknown pseudo-class. None of those declarations exists in any CSSOM, so an engine reading the CSSOM cannot see them, and `packages/essay`'s chapter fourteen has been open in every row for exactly this reason: `cases/26-what-the-flow-did-not-write` checks a named string as an absence. `:blank` has been built and unreachable since [*a parity is worth a page*](a-parity-is-worth-a-page.md) for the same reason. The same probe measured what the parser keeps: a custom property on an element, read back through `getComputedStyle`; `counter-reset` and `counter-increment` in the page context; a counter style in a margin box's `content`. And it measured what it does not keep even in that form: **a custom property inside `@page` or a margin at-rule is dropped**, which closes the door on reading a renamed declaration back from a page rule.

The checklist filed this as a design round on PLACEMENT rather than on a law: the architecture names a source-text pass as the path for GCPM properties, `src/` carries no dependency, `seam/` may carry one, BelType core ships css-tree, and a hand-rolled scanner would be a third parser in a project that deleted its unit table for being a second length engine. Three shapes were on the table (`packages/essay/book/PLAN-scenarios.md`, *The reader for dropped declarations*): the host hands the engine parsed facts; a narrow tokenizer in `src/`; the host rewrites the sheet so the browser keeps it and the capture reads it back through the CSSOM it already reads. One fact is fixed whichever is chosen: **the host must supply something**, because an adopted sheet keeps no text after `replaceSync`, so an engine that fetched `sheet.href` on its own would be blind in the editing tools.

## Decision

**Shape C. The host rewrites what the parser would drop into forms the parser keeps, the browser parses the rewritten sheet, and the capture reads the CSSOM — `src/` gains no parser, the ruling that the capture reads the browser's parsed rules stands, and the browser's own cascade resolves `string-set`'s specificity and non-inheritance rather than a reimplementation of it.** Ruled by Egildo on 2026-09-14 against A (three hosts deciding meaning) and B (the road every other paged engine took, each of which also owns layout, which is the posture this engine refused).

The encoding is a CONTRACT the engine publishes, one dependency-free module in `src/` that both the rewriter and the capture import, so the two halves cannot drift:

- **Element side, where a custom property survives and cascades.** `string-set: <pairs>` becomes `--beltype-string-set: <pairs>`, the value text carried verbatim; `position: running(<ident>)` becomes `--beltype-running: <ident>`. The engine registers both with `CSS.registerProperty({ syntax: '*', inherits: false })` at intake, so they cascade as the originals would and reach no descendant. The capture reads them with `getComputedStyle` while the source is still rendered — the document-state walk [*a counter is read at the start of the page*](a-counter-is-read-at-the-start-of-the-page.md) already performs is the seat, and it was built to be reused here.
- **Page side, where custom properties are refused.** A margin box's `content: string(<name>[, <which>])` and `content: element(<ident>)` are encoded as string literals carrying a reserved prefix — `"string(chap, first)"` — which the page context keeps as an ordinary `<string>` and `resolveContent` decodes; a concatenation keeps its other terms as they were. `@page :blank` and `@page <name>:blank` are encoded as a reserved page name the capture decodes back into the blank condition with `:blank`'s own (f, g, h) — the name carries the suffix `__beltype-blank`, so `chapter:blank` becomes `chapter__beltype-blank` and bare `:blank` becomes `__beltype-blank`; `:first`, `:left` and `:right` are left in place, since the parser keeps them. A selector list is split into one rule per selector with the block repeated.
- **Where the rewriter lives.** One implementation, in the engine's `seam/`, which may carry a dependency: css-tree, walked once, the same library BelType core already ships. `seam/` carries two dependencies from this round rather than one, and the convention that said *exactly one* was a description and not a law; the record states the change. The hosts that call it: the seam's own browser client (`seam/client.js`) and the essay's client (`packages/essay/lib/client.js`), which rewrite every same-origin linked and inline sheet in the document before the engine runs — replacing each sheet's node with a `<style>` holding the rewritten text at the same position, so the cascade order is untouched — and the editing tools' dresser, which calls the rewriter on each CSS closure entry's text before `replaceSync`. The oracle is never served rewritten bytes: Chromium's own print prints the document as authored, which the essay's runner already arranges by serving a print engine `native.html`.
- **What the encodings cost, named.** A reader of a rewritten sheet meets a prefixed string literal and a reserved page name and finds them strange; the console says once per document that the sheet was rewritten and why. Two encodings, stated as the price of keeping one parser.

**What this round builds on the reading side**, with the contract in place: named strings in full — `content()`, `content(text)`, `<string>`, `counter()`, `counters()` and `attr()` in a `<content-list>`, and `string()`'s four keywords with GCPM's own definitions (the entry value is the assignment in effect at the end of the previous page; `first` is the first assignment on the page or the entry value; `start` is the first assignment if the element is the first on the page and the entry value otherwise; `last` is the exit value; `first-except` is `first` except empty on the page where the value is assigned) — read from the document state at each entry's start and end; `:blank` reaching the capture; and running elements as far as the Chase can carry an element into a margin cell.

## Consequences

`src/` stays parser-free and dependency-free. The capture's one door — the CSSOM — stays the one door. The engine can no longer read a raw document that no host rewrote; every host that composes it must rewrite, and the seam publishes what. `string-set`'s `content(before)` and `content(after)` and `content(first-letter)` are read as `content()` and stated as a limit. Footnotes are outside this record; they are a design round of their own.

## Predictions, frozen before the build

1. `cases/39-the-running-head` and `cases/40-first-start-last` go green on both Cicero columns without their claims moving; Chromium's columns stay as declared (divergent in the margin boxes, printing empty boxes as it does today).
2. `cases/23-the-page-a-rule-selects` goes green on its new `marginBoxes` claim: the blank page loses the base rule's running head and wears the `:blank` rule's, on both Cicero columns.
3. `cases/26-what-the-flow-did-not-write`, which checks the named string as an ABSENCE, goes red on both Cicero columns — and is re-declared in this round to claim the presence, since the absence it pinned is what this round removes.
4. `cases/41-the-running-element` goes green on both Cicero columns: the Chase's `setMarginBox` carries a node rather than text for `element()`, the element leaves the flow at zero footprint the way a fixed box does. Low confidence — the cell is a shadow flex item and an author's sheet cannot reach it, so the moved element's own formatting must travel with it; if the round cannot carry it honestly the case stays red and the record says why.
5. No standing tally moves: a named string has zero footprint and touches no cut. The battery is run once at the close and the pin re-recorded.
6. The editing tools' acceptance tests stay green with the dresser calling the rewriter, and a Cicero pane there shows a running head from `string-set` for the first time — measured by hand once, since no test in that package reads a margin box.

## Verdict

**Prediction 1 held.** `cases/39-the-running-head` and `cases/40-first-start-last` are green on `cicero` and `cicero-composed`, every check, with their claims exactly as they were authored: four pages reading nothing, *Of the Whale*, *Of the Whale*, *The Carpet-Bag*; and twelve boxes over three pages answering `first`, `start`, `last` and `first-except` as §1.1.2 defines them, including the two that discriminate — `start` reading *Beta* on a page whose heading sits below a paragraph while `first` reads *Gamma*, and `first-except` reading nothing on both pages that assign. Chromium's columns stayed as declared and are still asserted divergent, printing every box empty.

**Prediction 2 held.** `cases/23-the-page-a-rule-selects` is green on its new `marginBoxes` claim: page three, the content-empty page the parity costs, wears THIS PAGE IS INTENTIONALLY LEFT BLANK and no folio, and pages two and four still wear the base rule's head and their own numbers. **What the prediction did not foresee is that two OLDER claims in the same file contradicted the new one**: `folio.absentOn` and `topBand.absentOn` named page one alone, because they were written while the `:blank` rule was unreachable and the blank page wore the base rule's furniture. Both name page three now, and the case's README says why — the `marginBoxes` claim beside them is strictly the finer reading of the same page, so nothing was weakened. Worth stating as the round's own small scar: **a coarse claim and a fine claim about one page will not notice each other going out of step, and the coarse one is the one that was written first.**

**Prediction 3 held, exactly as written.** `cases/26-what-the-flow-did-not-write` went red on both Cicero columns the moment the strings were delivered, on the two pages the reading says: *page 2: top band shows 'Later section' where the case declares it suppressed; page 3: the same.* That is the absence it pinned being removed, which is what it was pinned for. It is re-declared to claim the presence — its `topBand.absentOn` is page one alone, it carries `pageMarginsPt` and a per-page `marginBoxes` map, and Chromium's column is declared `marginBoxes: 'divergent'` with its own why. Its footnote half is untouched, and the chapter's caption says out loud that the claim was written the other way up and that going red is what produced the new paragraph.

**Prediction 4 HELD, and it was the one frozen at low confidence.** `cases/41-the-running-element` is green on both Cicero columns, and the browser's declared partition divergence is real for the first time — page one opens with the heading on the engine's columns and with the running paragraph on Chromium's. What made it hold is that the delivery is **not** what the prediction assumed. The prediction said the clone's own formatting must travel with it, and expected a per-property copy; instead the clone is **slotted** into the margin cell rather than written into it as text, on the Furniture's own two-kinds rule — a resolved value is not informational and goes into the page's cells, an authored box is and stays light DOM. So the clone never leaves the author's cascade and nothing has to travel: measured live, its `<em>` computes `font-style: italic` from the author's own `.rh em` rule and its `margin-top` is the `0` the author declared. What it does NOT carry is §1.2.1's other half — *"the element inherits from its original position"* — because a slotted element inherits from its flattened-tree parent, which is the cell: the head measured `font-size: 10.6667px`, the box's own 8pt, against the document's 9.5pt. That is a real limit and it is on the checklist; on a running head it is also, usually, what an author wanted.

**Prediction 5 is answered by the battery, in the round's own changelog entry.** Nothing else in the corpus declares any of the four: a grep over `seeds/`, `gates/` and `probes/` finds `string-set`, `position: running` and `@page :blank` in the four cases and nowhere else.

**Prediction 6 held on both halves, and the second half is the only thing in this round that found a real defect.** The editing tools' 48 acceptance tests are green with the dresser calling the rewriter. The hand measurement — `beltype edit` on a venue whose stylesheet declares a `string-set` running head, the pane's three `<beltype-page>` frames read through Playwright — reports `''`, `Of the Whale`, `Of the Whale`, which is a running head in a Cicero pane there for the first time.

**It reported nothing twice before it reported that, and the reason is worth the whole prediction.** `seam/csstree.js` began as `export * from 'css-tree'`, which resolves in Node and in the two hosts that are handed the library's browser bundle, and **fails in the editing tools' tab alone** — the one host that serves the file itself and resolves the package through its own import map. css-tree's main entry reaches `lib/version.js`, which imports `createRequire` from `node:module` to read its own manifest: *Failed to resolve module specifier "module"*. Narrowing to `css-tree/parser` and `css-tree/walker` fixed that and exposed the next one, `css-tree/generator` → `source-map-js`, a CommonJS package no browser can consume. The generator is out of the graph now and the rewriter reads the author's own bytes by offset instead — which is what it does everywhere else, so the import that had to go was the one that least belonged. **`css-provenance.js` had already gone through exactly this door for exactly this reason**, and its narrow `css-tree/parser` import was the standing evidence nobody read before writing the wide one. Both failures were LOUD — a console line saying a named string would not reach the preview, and a pane that rendered everything else correctly — which is the shape the optional load was written to have; neither would have been found by any test in any package.

Three hosts, three different answers to one specifier, and only one of them can be checked by a suite. That is the honest cost of the arrangement, and it is why the prediction asked for a hand measurement.

**The seam host's own proof, by hand, once.** A scratch venue whose stylesheet declares all four constructs, served by `node bin/beltype.js <file> --engine cicero`, read through Playwright: three pages, and `[data-box="top-center"]` reads `''`, `Of the Whale`, `Of the Whale` — GCPM's `first` with no second argument, the entry value on page one being empty because nothing has been assigned. The console carries one line naming what was rewritten. The repository's own `test/specimen.md`, whose stylesheet has declared `string-set`, `position: running()`, `string()`, `element()` and `@page :blank` since long before any of them worked, now prints its chapter titles in its own running heads.

**What was too good to be true, checked — and one thing that was not true at all for an hour.** The `element()` chain reported success while delivering nothing: the essay's client was passing `running` to `present()` in one door and not the other, and the margin cell came back with an empty string rather than an error. The reason is worth the line: `#runningPart` answers an identifier no element claims with `''`, which is the right answer for an author's typo and indistinguishable from a host that forgot to hand the map over. Caught by reading the live cell's `innerHTML` rather than the case's verdict.

**A second thing found by measurement rather than by reasoning.** `chase.js`'s intrinsic-width cache key contained two NUL characters as its separators — committed, and invisible to `grep`, which reports the whole file as binary and matches nothing in it. They are gone with the line that carried them; nothing depended on them, since the key is only ever compared against itself. Filed here because the next session to `grep` that file would have met the same silence.

**And one change nobody predicted, forced by the rewriter's own placement.** `vendorAssets()` published `src/` FLAT beside the client under `cicero/`, which is why `seam/client.js` imported `./driver.js` and could be resolved in a browser and nowhere else. The rewriter imports the encoding contract out of `src/`, and no single specifier names that both on disk and under a flattened URL — so the table publishes `seam/` at `cicero/seam/` and `src/` at `cicero/src/`, the two prefixes are disjoint, and every import in `seam/` is now an ordinary relative path that resolves in both places. The one entry that is still written against its served location is `csstree.js`, and it has to be: Node resolves the package, a browser is handed the library's own bundle at the same name.
