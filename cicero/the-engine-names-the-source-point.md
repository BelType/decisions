# The engine names the source point

**Status: Decided 2026-10-13, Executed 2026-10-13.** Supersedes the "Elements only" paragraph of [*the engine names the source*](the-engine-names-the-source.md), which refused character level and reserved a `(gi, char)` refinement; that refinement stays unminted, and what replaces the refusal is a pair of verbs in DOM terms.

## Context

An editor host places a caret, reads a selection or paints one across a page break by turning a point inside a copy — a first fragment, a continuation, a composed block's clone, a fixed box's per-page copy — into the same point in the source, and the reverse. It had `sourceOf`, which answers for ELEMENTS, and nothing for text. So it paired the copy's text node with the source's by position and recovered the character offset by aligning the copy's string with the source's, a heuristic that sat outside the engine, which knows exactly what it blanked.

The pairing breaks where a copy puts a box away HOLLOW (*the clone is hollow outside the interval*): a spent `<em>` keeps its tag and loses its children, so the text node the source has inside it is gone, and every walk that pairs text nodes by order is off by one after it. Measured by that host painting a selection on a continuation holding an `<em>`: nothing was painted, silently, until it paired by parent element and child index. The alignment of offsets was worse in a quieter way. Consuming a fragment's words blanks the words and leaves the whitespace between them, so a first fragment's data ends in the spaces of every word cut away and a continuation's begins with them: a string comparison finds those spaces in the source at the wrong place, and cannot say they belong to no page.

Egildo ruled on 2026-10-13, between two ways that had been weighed (NEEDED-FIXES, *a copy's text cannot be mapped back to its source by position*): (a) a seam verb at character level, beside `sourceOf` and `pageOf`; (b) a hollow box keeping an empty text node where the source has one, so child indices stay one to one for text too. **(a).**

## Decision

**Two verbs on `<beltype-root>`, published on the host handle `window.__beltypeCicero` beside `sourceOf` and `pageOf`, and typed with them.**

`sourcePoint(node, offset)` answers `{ node, offset }`, the source point of a DOM point inside a presented copy. `node` is a Text node (`offset` a character offset) or an Element (`offset` a child index), as in a DOM boundary point. A point in an ORIGINAL is answered unchanged: it is the source.

`pointOn(sourceNode, offset, page)` answers `{ node, offset }`, the point on page `page` (zero-based, `pageOf`'s own convention) that SHOWS the source point: the original itself where that page presents the original, else the copy's point. A source point at a page break is shown at the end of the page before and the start of the page after, and each page answers its own. The page's content is built if it is not built yet.

**Exact, never aligned.** Every copy's text node is registered against its source's at the moment the copy is made, with the element registration (`word-space.js`' `mapCloneToSource`), and the registration is a record of RUNS — stretches of the copy's current data that are still the source's characters, clone offsets against source offsets. Every removal from a copy's text goes through ONE door, `cutRanges`, which trims the runs as it trims the data (`emptyText` for a box put away, the blanking in `consumeLeadingWords` and `consumeTrailingWords`), so no site can remove a character and forget to say so. The Compositor's `splitText` goes through `splitTextAt`, which hands the tail its share, so the composed mode's pieces answer as the whole text did. The soft hyphen written as the hyphenation character at a cut is a replacement and goes through `replaceChars`: one character for one character maps one to one and records nothing; the empty string the property allows, or several characters, is a removal and the engine's own text, which has no source. The record costs what was removed, never the length of the text. **Nothing is written on the DOM** — WeakMaps only, no attribute, no expando.

**The interval is not the data.** The whitespace a consumed word leaves behind is on the far side of the cut: held by the copy, in no page's fragment. The consumers say so (`leaveOut`, from `fragments.js`' `leaveOutBefore` and `leaveOutAfter`: every character before the first kept word, every character after the last, and every text node wholly outside), the runs carry an `out` mark, `sourcePoint` still names such a character — it IS the source's, exactly — and `pointOn` does not show it. That is what makes the end of a paragraph's first fragment answer `null` on the page it was cut off from, and the two sides of a break answer different points: `zeta|` at the end of one page and `|eta` at the start of the next, with the space between shown on neither.

**What `null` names.** For `sourcePoint`: a point in nothing the author wrote — an engine mark (the Compositor's break and filler, the slice shell), text the engine wrote (the hyphenation character), a node outside the root, a box the copy put away (nothing is shown inside it, and a hollow one has no children to point into), a text node with none of its characters left. For `pointOn`: this page does not show that source point — the character is not in its fragment, the box holding it is hollow or put away there, or there is no such page. Both verbs answer `null` rather than guess, and a host can tell the cases apart by what it is holding.

**An element point is structural.** `sourcePoint(el, i)` is the boundary before the same author's child in the source, skipping the engine's marks (which shift the copy's child indices) and answering a text point where the child is a later piece of a split text, which begins inside its source node. `pointOn` is the reverse: the copy's child index of the first author's child at or after the source's. Child indices of elements stay one to one under put-away boxes, which keep their place; engine marks are what moves them. An element point claims nothing about what is shown.

Refused: **(b), a hollow box keeping an empty text node.** It would restore the index pairing for text nodes and still leave every offset to the host — the heuristic would only move one step down — and it would put engine bookkeeping into the copy's tree, where a `:has()`, a `:empty` or a child-count selector can see it (the reason the hollow box is hollow). Refused: **publishing the map**, which hands live DOM references across a seam the engine may one day leave the realm by, the argument that made `pageOf` and `sourceOf` verbs. Refused: **stamping the clone** with its source offset, an attribute or an expando, which writes an engine fact into the author's markup where a stylesheet can match it. Refused: **a host-side alignment kept as a fallback**, the heuristic this entry exists to remove.

## Predictions, frozen on write

1. **Registration is invisible to layout.** The records are WeakMaps and the text writes land on the same strings in fewer calls (one data write a node instead of one a word). Hold: every standing gate reproduces and no record moves. Break: any page count, divergence tally, positional or conservation gate changes.
2. **The DOM-free suites do not see it.** Their trees have no `childNodes` on the elements the registration walks and no registered text; the consumers' walks over text go by `childNodes`, as `joinedWords` reads. Hold: the engine's own suite is green unchanged.
3. **Expected to be unable to say:** a comment node's place (elements and text only), and whether a caret in a collapsed whitespace run of an ORIGINAL is drawn (it answers itself).

## Consequences

`src/word-space.js` gains the text record and its writers (`noteText`, `cutRanges`, `emptyText`, `replaceChars`, `leaveOut`, `splitTextAt`) and its two readers (`sourceTextPoint`, `textPointShowing`); `src/source-point.js` is the new module holding the two verbs' logic, DOM-aware and checked; `src/fragments.js` routes its removals through the door and says what lies outside the interval; `src/compose-dom.js` splits through `splitTextAt`; `src/root.js` seats `sourcePoint` and `pointOn`; `seam/client.js` publishes them. The editing tools' handle type gains the two members. A host that aligned strings or paired text nodes by order deletes that code.

**Caster is deliberately not changed.** Its adapter pairs by rule and keeps working; what it may do with the verbs is its own round's question, as with `sourceOf`.

The pin is `packages/essay/test/source-point.test.js` in both modes, over a paragraph that straddles a page break with an `<em>` and a `<strong>` before it, so that on the continuation both are hollow and the text nodes sit at the source's child indices: every character of both fragments is the source's own character; the first page shows exactly the offsets up to the end of its last kept word and the second exactly those from the start of its first, with the separating space on neither; every point the verbs answer sends back to where it started; an original answers itself; a stranger and a page that does not exist are refusals; the Compositor's marks answer `null`; element points past the hollow box land on the right child. It was made to fail twice before it was trusted: first for want of the verbs, then with the Compositor's split put back to `splitText` (the composed mode goes red) and with the interval's `leaveOut` removed (both modes go red). A DOM-free unit test in `test/word-space.test.js` states the record's algebra without a browser.

## Verdict

**Prediction 1 held.** The whole battery ran against the committed source: 26 gates of 26 in 16.6 minutes, every standing record reproduced unmoved — native 163 agree, 18 legal-divergence, 7 theirs-illegal, 11 unclassified, 1 reference-invalid; composed 89 and 86; the view gates 50, 40 and 30 view-agree; conservation green — and the pin was re-recorded at the branch's last commit (`npm run pin` says the records stand).

**Prediction 2 broke, and was one line.** The engine's DOM-free suite went red in eight tests on the first run, because the new walk over a clone's text nodes asked the node for its `ownerDocument` and those suites' trees have none. `joinedWords` walks by `childNodes`, and so do the new walks now (`textsIn`); the suite is green unchanged, 311 tests with the two added. A walk by the DOM-free suites' own shape is the house rule for anything `fragments.js` does to a clone's text.

**What was too good to be true, and was checked.** The default-mode pin passed on its first green run, so it was mutated: with the Compositor's split put back to `splitText` the composed mode goes red; with `leaveOutBefore` and `leaveOutAfter` commented out both modes go red. The pin's first draft had also assumed a continuation's leading text is an empty node. It is not: consuming a word leaves the spaces around it, so the copy holds the source's spaces in no page's interval, which is why `leaveOut` exists and why an offset past the end of a first fragment answers `null` where a plain record of what was removed would have answered a point in invisible whitespace.

**Unpredicted:** the whitespace. The brief and the first sketch recorded removals; the interval turned out to be larger than the data the copy keeps, and the record had to learn that difference. A caller that wants the page of the end of a paragraph asks exactly the question the difference decides.
