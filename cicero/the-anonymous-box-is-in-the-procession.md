# The anonymous box is in the procession

**Status: Decided 2026-09-29, Executed 2026-09-29.**

## Context

A block container holding text beside block children had no line stack to the Gauge and no box for the text in its procession. `linesOf` answers empty for any box with block children, and the procession the Stonehand ranges over was `word-space.js`' `blockChildrenOf`, the element tree's block children. So a line standing before the first block child or after the last was read as nothing but the distance it opened: `gapAt`'s start gap ran from the content edge to the first block child's margin edge, and `endGapOf`'s base was the last block child's bottom. The checklist's entry *the Gauge's half of the block-seam rule is unexercised* had said, since 2026-09-10, that nothing in the venue drew such a box; a real venue's contents page drew one on 2026-09-29, and [`cases/76-the-line-before-the-first-block`](https://github.com/egildo/beltype/blob/42b348b547d269a217a7f193042fe216386a4650/packages/essay/cases/76-the-line-before-the-first-block/README.md) reproduced it on the small page, red in both modes on three page heads and on totality.

The case README carries the arithmetic. Under a heading kept with the box, the start gap answered to the heading's `break-after: avoid` across the line, every candidate on the page violated, and the make-up order kept ten list entries under the line where Chromium takes the Class A point after it. After the last block, the end gap was offered because the box ended past the edge, and a cut in it shelled thirteen lines blank: `c0w018` to `c0w025` were on no page. And in the venue's own shape, with nothing kept before the box, the false start gap was the only thing standing where the missing Class A point should: the page came out right for the wrong reason, which is why a fix that only removed the gap would have turned it red.

## What the text says

CSS 2.1 §9.2.1.1: *"if a block container box … has a block-level box inside it …, then we force it to have only block-level boxes inside it"*, the inline content wrapped in anonymous block boxes, whose properties *"are inherited from the enclosing non-anonymous box"*, non-inherited ones at their initial values. css-break-3 §4.1 then places every point: a Class A point *"between sibling boxes of the following types: … in-flow block-level boxes"*, the anonymous one among them; Class B points *"between line boxes inside a block container box"*; and a Class C point only *"between the content edge of a block container box and the outer edges of its child content (margin edges of block-level children or line box edges for inline-level children)"*, where a line is child content, so there is none where a run stands. §4.4 rule 1 binds the Class A point to the `break-after` and `break-before` values applicable to it: the anonymous box's are `auto`, and the neighbour's are its own.

## Decision

**The procession of a block container is its block-level children and its anonymous block boxes, one per maximal run of inline content standing before, between or after them.** The Gauge builds each run as a box of its walk: `el` is the container, whose pitch the lines are set on and in whose word space the run's words are counted; `anonymous: true`; its lines are the run's words read by the same `home`, `lineBoxOf` and `pitchOf` as any line stack's; its `rect` is those lines' extent, read when first asked. It has no decoration and no gap (`endGapOf` answers null), every break property is `auto`, and its `orphans` and `widows` are the container's, the two inherited properties the walk reads (`stonehand.js`' `anonymousStyle`). It enters the container's `blockChildren` at its place and the box list at its place in document order, so the Stonehand's Class A, Class B and stop-at-the-edge readings take it with no branch of their own, and `gapAt`/`endGapOf` read the procession that now holds it: a leading run makes the start gap zero, since a first line box stands at the content edge, and a trailing run is the last item the end gap is measured from. A run holding no word is no box — whitespace alone, or an inline image alone, which is the limit a paragraph holding one image alone already has.

**`blockChildrenOf` stays the element walker.** The forcing index, the page's name and the address all walk elements, and a run has no element; the Gauge is the one reader that needs the run as a box, because it is the one that reads lines. A display whose inline content is not wrapped in anonymous block boxes — flex, grid and table containers, whose runs are anonymous items and cells — gets none.

**The address.** A run has no path of its own, so a cut that names it names its container:

- **A Class B point inside a run** is `{ path: [...container], word: w }`, `w` in the container's joined-word space, which counts its block children's words before the run too. The driver's Class B branch mints it unchanged: `wordsOf` on the anonymous box answers the Gauge's word index over the container, which is that space.
- **The Class A point after a leading run**, before the first block child, is the bare path to that child. `normalizePath` used to drop a trailing zero there, and a run standing before a first child makes that zero a place: before the child is after the line. So `cutTo` keeps the zero where the position index counts a word before the child in its parent (`wordsBefore(child) !== wordsBefore(parent)`), and `nameAt` stops its first-child descent at the same test. That moves one more thing than the case: a forced `break-before` on a first element child after a run was minted as the container's own start, so the grab cut the feed before the whole container and the run went to the next page with the child; it is minted at the child now, and the scratch document below draws it and agrees with Chromium.
- **The Class A point before a run that follows a block child** is the run's first word, `{ path: [...container], word: w }` — a Class B address at the run's first line. The other spelling open was the bare path to the next block child, which is after the run and would put the run on the page before, and a trailing run has no next child at all. The word spelling holds at every run.

**Consuming through block children** is sound, and it is the same rule, not a new one. `consumeLeadingWords`' sentence — *wordless means already shown is sound where word order and line order are the same order* — holds in a container cut at a word of a run, because everything standing before that word's text in document order, block children included, is before the cut: the block children before the run are blanked and the structural pass puts them away. The end side needed one clause: `consumeTrailingWords` put away every wordless element after the last kept word, and a wordless BLOCK standing between the last kept word and the run — a figure after the paragraph before it — is before the cut. So a non-inline element standing wholly before the first dropped character stays. Inside a line stack no block stands there, so a leaf reads as it always did. `fragmentOf` builds both ends with the two functions, end first, and needed nothing else.

**Order.** `positions.js`' `cutAfter` compared paths lexicographically, a shorter path the earlier place, which is right for a bare path and wrong for a word in a container: `{ [P], word w }` in a run after child k is AFTER `[P, k]`, and the lexicographic order put it before, so the C2 check threw *the walk failed to advance* and the forcing index's search would have found a forced event behind the cursor. Where one path runs inside the other and the shorter carries a word, the two are ordered by their flat projections, and at an equal one the word comes after: a box inside the container starting at the run's first word is a wordless box standing before the run, since a run holds a word. The driver passes its `posOfCut` at all five of its calls and to the forcing index; `comparePos` needed nothing, since it already orders by the projection.

**Consumed words one level up.** The driver's `consumedIn` converted a word the Gauge read on a clone to source coordinates only where the cursor named the same leaf by word. A container resumed at a bare path into it — after a leading run, or at a block child — has put away everything before that place, so its clone's word zero is the cursor's projection less the container's start; `consumedIn` and `consumedAnywhere` now answer that where the cursor's place lies inside the leaf. A true leaf never holds another box's place, and reads zero as before.

## What the rivals do

Every rival builds the box, and this record took the box and refused the address.

- **fragmentainers** (`layout/layout-node.js`, `layout/anonymous-block-node.js`, `algorithms/block-container.js`). A mixed box's child enumeration wraps each run of significant inline nodes in an `AnonymousBlockNode`, whose break values are the base class's `auto` and whose `orphans`, `widows`, `white-space` and line-height are read off the element that holds it — the same as `anonymousStyle` and the container's pitch here. `#updateBestEarlyBreak` scores every boundary between children, the anonymous one included; the run is an inline formatting context divided between its lines. Its break token carries the layout node itself in a tree mirroring the box tree, anonymous nodes included. **Taken**: the box, its `auto` values, its inherited `orphans`/`widows`. **Refused**: grouping over DIRECT child nodes only — this procession already descends through an inline box to the blocks inside it (block-in-inline), so runs are gathered in the same walk.
- **WeasyPrint** (`formatting_structure/build.py`'s `inline_in_block`, `layout/block.py`). The anonymous box is built before layout, and a break inside it is addressed in the skip stack by its index among the container's children, anonymous boxes counted. **Refused**, for this engine's address: a path indexes the SOURCE's element children, resolved on the source and mapped onto clones, and the source has no anonymous box — so the container's path and a word in its word space stand where WeasyPrint's child index does.
- **Paged.js classic** reads rects of text nodes and elements alike, with no box and no gap; nothing to take.

## Audit

Every reader of a Gauge box, asked what it does with an element-less one.

- `gauge.js`: `walk` and `byEl` register element boxes only, so `boxOf` never answers an anonymous one; the rows loop runs on flex, grid and table-row containers, which get no anonymous boxes; `measureWords` numbers every word of the container and reads only the run's (`slotOfText`); `pitchOf` reads the container's line-height and, where it is `normal` on a one-line run, the run's own strut, never the container's content box; `endGapOf` null; `gapAt`'s start answers zero where the first child is a run.
- `stonehand.js`: `styleOfBox` answers `anonymousStyle`; `monolithic` false; `insideMonolith`, `insideParallel`, `insideRowItem` walk its parents, as they should; `parallelBox` false through the style; `rowOf` null; `bottomOf` its rect; `clonedBlockEnd` skips it (`slice`) and charges its ancestors; `breakAfterAvoid`/`breakBeforeAvoid` now stop at a run standing first or last in a container, which is §3.1.1's propagation read on the real first and last child; `edgeStraddler` skips it, so the edge slices the box that holds its lines; `neverCutInside` and `isMonolith` are never asked of it.
- `driver.js`: `itemOf` walks its parents; the Class A and Class B branches mint the addresses above; the edge and end-gap branches never meet it; `placesOf` gives a run wholly below a carried flow's cut its first word, and does not ask `isMonolith` of it; `spentLeadOf` and `inFlowBottom` read element boxes only.
- `fragments.js`, `positions.js`, `root.js`: as above; `root.js` builds every fragment through `fragmentOf`, `continuationClone` and `firstFragmentClone`, so the presentation reads the same cuts the measure feed was built with and changed in nothing.

## Consequences

The checklist's block-seam entry closes with this record, and its §4.1 row says a line beside block children is child content; `architecture.md`'s Gauge section and its address section describe the anonymous box and how a run is addressed; `.claude/NEEDED-FIXES.md`'s row moves to Closed; the book's §4.1 row says what is true. What it leaves standing:

- **The venue's contents page keeps its title alone on its page**, and that is right. Its `li, cite { break-after: avoid }` makes every boundary inside the list a violation, so the Class A point after the title is the one clean cut; Chromium does the same, measured in the case. Do not reopen it as an engine fault.
- **A forced `break-after` on a block child followed by a trailing run** lands on the next ELEMENT box, after the run, where §4.1 puts the forced break at the boundary before the run: the forcing index's events are element starts, and a run has none. Reasoned from the index, not measured, and no document draws it; filed on the checklist.
- **How violations are weighed** where every point on a page violates — the nested entry the case README measured beside it, where Chromium's point violates one keep and the engine's two — is P21's binary order, unchanged and not this record's.
- **A run of inline content in a flex, grid or table container** is an anonymous item or cell, not a block box, and is not built here.
- **An inline atom's vertical margins** are outside the line box the Gauge reads (it reads the atom's border box), so a run ending in an inline-block with a bottom margin ends above where Chromium's line box does: the venue's title reads 40px where Chromium's line is 52. The Class A point after it is then priced 12px higher, which moves no cut in the case and none measured.

The tablet is untouched: I3's classes are the text's, and this record makes the procession the one the text describes.
