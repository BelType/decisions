# The box on every page

**Status: Decided 2026-09-07, Executed 2026-09-07.**

## Context

The design round of 2026-08-04 gave the Furniture a second duty and left it unbuilt. Its duty is **everything that reaches a page from outside the flow**, and there have been two kinds since that round: a resolved **value** — a page number, a running head — which is not informational, so I6 does not reach it and it is written into the page's own cells; and an authored **box**, which is informational, so I6 does reach it and it stays light DOM, slotted. The second kind has exactly one member, and CSS 2.1 names it: *"For paged media, boxes with fixed positions are repeated on every page"* (§9.6.1), *"the box is rendered on every page, and is fixed with respect to the page box"* and *"UAs must not paginate the content of fixed boxes"* (§9.3.1).

Nothing was built. A `position: fixed` element was an ordinary top-level block: `topLevelBlocks` returned it, `indexBlocks` gave it a place in the word space, the feed carried it, the Gauge measured it, and it was slotted onto whichever page its words fell on. What `cases/24-the-repeated-box` measured as *repetition* was **the browser's**, not the engine's — Chromium's own print obeying §9.6.1 on a document whose fixed element the engine had put inside a page, and repeating it against the **sheet** because the presented page carries no CSS page margin. The case recorded that as a placement divergence of one whole page margin, x 34.2pt against x 5.7pt, *"the kind of thing that would otherwise be discovered as a bug"*.

## Decision

**The Furniture delivers it, and the placement is a reading of two sentences rather than a choice between them.**

**One — a fixed box leaves the flow entirely.** `topLevelBlocks(doc)` no longer returns it and `fixedBoxes(doc)` does. The Model's answer for a fixed box is **zero**, the same answer chrome gets, and zero footprint means what it says: no position in the word space, no place in the feed, nothing for the Stonehand to rank. The flow then behaves exactly as it would if the element were not in the document, which is what §9.6.1 requires and what case 24 measures. **Refused: giving it zero WORDS while leaving it in the block list**, which the assessment proposed — a block with no words still has a place in the procession, an index in `bases`, and a rect the Gauge reads, and every one of those is a way for a zero-footprint box to be found to have a footprint after all.

**Two — N pages means N clones, and that is forced rather than chosen.** A light-DOM element can be assigned to one slot only, so one element cannot be on two pages. The clones are decision products under C5, exactly as continuation clones are, and the source is never written — which is why the `position: absolute` that re-homes them lands on a class the dressing sheet carries and not on the author's own element. The original stays in the light DOM, unassigned and unrendered, canonical, the arrangement composed mode already uses for a hinted block; every clone after page one is `aria-hidden`, so the document is read once. **Hidden by PAGE and not by clone index**: a second fixed box on page one is a different box and owes its own reading.

**Three — the containing block is the page area, and both sentences survive.** §9.3.1 says the box is *"fixed with respect to the page box"*; §9.6.1 says *"parts of the fixed position box that are not visible in the initial containing block will not print"*, and css-page-3 §3 says *"the edges of the page area on the first page establish the rectangle that is the initial containing block"*. Those are two different rectangles and a page margin apart. They are not in conflict once they are read as answering different questions: **the page box is what the box is anchored to** — that is what *fixed* means, and it is why the box does not travel with the content — and **the page area is the rectangle its offsets resolve against and the rectangle it is clipped to**, because that is the initial containing block §9.6.1 names. The clone is therefore `position: absolute` against `.content-area`, the one positioned box in the page frame's shadow, whose content box is the page area.

Chromium is evidence and not authority here, and it agrees: a 2mm offset inside a 10mm margin prints at the margin plus 2mm, not at the sheet's corner. The reading was taken from the two sentences and then checked against it, in that order.

**Four — the clip needs no code.** `.content-area` already carries `overflow: clip`, so §9.6.1's *"boxes with fixed position that are larger than the page area are clipped"* falls out of the containing block being the page area. Nothing was written for it, and that is the argument for the seat rather than a convenience of it.

**Five — the monolith predicate gains the tablet's third ground.** The Cut names three: the inherently unbreakable, the zones the spec leaves to engine choice, and **the normatively forbidden**, *"the strongest of the three and the only one that is not a judgement call"* — §9.3.1's prohibition on paginating a fixed box's content. It had never been built. A top-level fixed box no longer reaches the predicate, having left the flow; a nested one does, and this is what refuses to cut through it.

**Six — a blank page takes its fixed boxes.** §9.6.1 says *every* page. A page's blankness is a fact about the FLOW: css-page-3 §3.2 calls a page content-empty when its page area carries no printable content, and §4.2.3's own example leaves a page number on such a page — so furniture no more fills a blank page than a running head does.

**Refused: reaching a nested fixed box.** The mechanism carries top-level boxes only. A `position: fixed` element inside a flow block travels with its block and the browser's print then repeats it against the sheet. Lifting a box out of a clone the fragment writer builds is a different mechanism with no customer yet, and it is the same limit round 07 left on carried flows, stated for the same reason.

**Refused: laws.** None moves. This is the Model's *zero* answer built, and the Furniture's second delivery built as the 2026-08-04 round designed it.

## Predictions

Frozen on write.

1. **`cases/24-the-repeated-box` keeps its three pages and its boundaries, and its recorded placement divergence closes** — the box landing at the page margin plus its own offset on both columns. *Breaks* if the boundaries move, which would mean the box still had a footprint, or if the placements still differ, which would mean the reading of the two sentences was wrong.
2. **Case 24's `topBand` claim stops holding, and that is a correction rather than a regression.** The box was in the top band only because it was in the wrong place. *Breaks* if it is still in the band, which would mean the box had not moved.
3. **A new case with a box taller than the page area shows the clip on the engine's columns and §9.3.1 violated on Chromium's.** *Breaks* if the engine prints an outside line anywhere — the clip is the claim — or if Chromium turns out not to paginate the box, which would make the row settled rather than divergent and would want P32b re-read.
4. **Every other case is unmoved.** No other case and no seed draws a fixed box.
5. **`cases/acceptance.js` keeps its pinned 12 pages in both modes.**

## Verdict

**Prediction 1 held, and the placement closed to a fifth of a pixel.** Case 24 prints three pages on every column, block four opens page two and block seven page three, and the box lands at **x 45.3 CSS pixels against Chromium's 45.5** — a 10mm margin plus a 2mm offset, where the case had recorded a whole page margin between the two columns. The y differs by one pixel, which is the Chase's own documented print-safety inset and not a positioning difference.

**Prediction 2 held, and it bought more than it cost.** The `topBand` claim went red on the first run and is gone from the declaration with the mis-placement it rested on. What replaced it is stronger: with the box inside the page area it is ordinary printed text to the reader rather than furniture in a margin band, so `ignoreTextPattern` went too and the two columns are now compared **word for word including the box's own words**. `partition: identical` therefore asserts that the engine draws the box on the same three pages Chromium draws it on — the repetition, stated positively, against an oracle that repeats. It had been asserted before by a band check that was passing on the defect.

**Prediction 3 held on both halves.** `cases/32-the-box-that-is-too-tall` — a 140mm rail against a 70mm page area, four lines inside it and four fifty millimetres below, no line anywhere near the boundary — prints the inner four on both pages and the outer four on neither, at the same x and y as Chromium's own inner four. Chromium repeats the inner four correctly and prints the outer four on page two as well: the streams are identical on page one and differ on page two by exactly eight tokens. Declared `divergent` with the argument, and gated nowhere.

**The counterfactual is the sharpest number in the round.** The same document run against the whole pre-round tree — engine and venue client together, extracted to a scratch directory — presents **three pages**, and pages two and three both *open* with `Far one. Far two. Far three…`: the rail was in the flow, took room, was cut across pages, and pushed the document past its arithmetic. Block four begins no page at all. One document says the whole defect.

**Prediction 4 held.** The whole case suite was run and diffed against the previous round's run: identical, line for line, with case 32's own heading added. 27 checks failing before and after, the same thirteen cases.

**Prediction 5 held.** 12 pages presented and printed, native and `--composed` alike.

**Too good to be true, checked.** Case 24 passed on the pre-round tree with its old declaration, which is what a green looks like when the check has been fitted to the defect: the band claim held because the box sat where nothing had decided it should, and the totality check was off for an unrelated and correct reason, so nothing in the file could see it. The case is not weaker now — it is checking the thing it always said it was about.

**One thing was found and not fixed, and it cost a measurement in this round.** `cases/runner.js` still has no per-case `catch` ([NEEDED-FIXES](https://github.com/egildo/beltype/blob/42b348b547d269a217a7f193042fe216386a4650/.claude/NEEDED-FIXES.md) §4.1). The first run of case 24 after the engine change threw inside `page.evaluate` — a backtick in a comment inside a template literal, an ordinary mistake — and took the whole battery with it rather than one case; and the counterfactual above could not be run through `ENGINE_DIR` at all, because the venue's client imports `fixedBoxes` and an engine without it fails to load, again killing the run. Extracting the whole tree was the way round it. That is the second and third time §4.1 has cost something in these rounds.

**The battery ran at the close of the rounds (2026-09-07), and no standing number moved for this round — checked by a counterfactual rather than by a tally.** The three gates whose tallies the run disagrees with — `native` (0–199), `composed-v2` (200–299 `--composed`) and `v3-native` (400–449) — were each run a second time against the **pre-round `src/`**, the tree at `1cce345` reached through `ENGINE_DIR`, and the two runs' reports are **identical seed for seed**: 164/18/11/7 native, 84/12/4 composed-v2, 42/6/1/1 v3-native. The comparison also settles this round's own wall, the one the counterfactual could not be run through last time: the pre-round tree was reached through `ENGINE_DIR` after all, with `fixedBoxes` shimmed to return an empty array — which is not a concession but this round's own structural argument written as code, since an empty array is exactly what the pre-round engine did with a fixed box, and the corpus draws none. So the argument is measured: no seed reaches `fixedBoxes`, `topLevelBlocks` returns what it returned before, and `present`'s new loop iterates nothing. **The three disagreements with `gates/records.js` are identical before and after these rounds and are therefore not the engine's**; they are the machine's, the record is left standing, and the account is in the repo [CHANGELOG](https://github.com/egildo/beltype/blob/42b348b547d269a217a7f193042fe216386a4650/CHANGELOG.md) and in the [checklist](https://github.com/egildo/beltype/blob/42b348b547d269a217a7f193042fe216386a4650/packages/engine-cicero/docs/css-paged-media-checklist.md) §7. The pin is not rewritten — only a complete run with every gate green may write one, and `cases` and `suite` are red here on a font substitution.
