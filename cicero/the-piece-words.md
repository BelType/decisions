# The piece words

**Status: Decided 2026-10-11, Executed 2026-10-11.** Step 2 of `.claude/plans/cicero-optimisation/data-beltype.md`, ruled by Egildo on 2026-10-09, 2026-10-10 and 2026-10-11 (the three sections of rulings in that note; the census beside it is `one-attribute-census.md`). Step 1 is [*one attribute has words*](one-attribute-has-words.md).

## Context

Cicero shows a page through copies of the boxes on it, and it marked those copies, and the elements it creates, with classes on the author's own boxes (`__beltype-cont`, `-cut`, `-first`, `-fixed`), three more on its own elements (`-slice`, `-break`, `-fill`), an attribute (`data-beltype-fragment`), an inline `display: none !important` on a box it put away, and a run of inline styles that truncated a continuation (`margin-top`, `text-indent`, `border-top-width`, `padding-top` and the bottom mirror). The belt's line stamp was an attribute of its own (`data-beltype-pos`), read and compared whole by five packages.

Two harms, one measured and one found by this round. A class on an author's box changes what `:not([class])` and `[class="a"]` match on a copy (measured, step 1). And an inline declaration is the weakest thing the engine could have written: it overwrote an author's own inline `style`, and **it lost to an author's `!important`, layered or not** — found here: a division with `padding-top: 40px !important`, divided across pages, drew the padding again on every continuation and ran to three pages where Chromium's print runs to two (`cases/103-the-truncation-beats-the-author`, ten pages against eight on the commit before this one).

## Decision

**Every mark is a word of `data-beltype`.** The table is in the registry (`src/data-beltype.js`) and, for an author, in `reference.md`. The old spellings and what they became:

| Was | Is | Note |
| :-- | :-- | :-- |
| `data-beltype-pos="135"` | `pos:135` | the START line only; core writes it (its own literal, pinned), appended to whatever the element says |
| `data-beltype-fragment` | `fragment` | the root of every copy appended to `<beltype-root>`; Caster writes it too, on a span it lifts out of a margin cell |
| `__beltype-cont` | `split` without `start` | the opening cut divides the box |
| `__beltype-cut` | `split` without `end` | the closing cut divides it |
| `__beltype-first` | `split` with `start` | a constructed first fragment |
| `__beltype-fixed` | `fixed` | a `position: fixed` box's per-page copy |
| `__beltype-slice` (the wrapper) | `shell` | the painted shell's wrapper; not the key `slice:N`, which is a different thing with a near name |
| `__beltype-break`, `__beltype-fill` | `break`, `fill` | the Compositor's own `<br>` and filler `<span>` |
| inline `display: none !important` | `away` | |
| inline zeroing of margin, indent, border, padding | the words `split`/`start`/`end` plus `wrapped` and `adjoin` | rules in a sheet |
| `data-beltype-rewritten` | deleted | nothing read it |

The decision records written before this one (`the-cut-divides-its-ancestors`, `every-branch-gets-a-place`, `the-first-fragment-is-constructed` and the rest) say `__beltype-cont` and the others: read them through this table.

**`start` means "dressed as the box's beginning", not "holds it"** (ruled 2026-10-11). A piece that is `start` keeps the box's `::before`, marker, first letter, top edge and indent. That covers the painted shell, which is divided and yet dressed as a start — the box a page edge slices keeps its own top decoration, drawn on the page before and riding above the clip — so it is `split start` (and `end` unless the closing cut also passes through it) with no word of its own. `split`, `start` and `end` are read as a pair of facts: *cont* is `split` without `start`, *cut* is `split` without `end`, a middle piece is `split` alone. `markCont` and `markCut` (`fragments.js`) read the state the words already hold, so they compose in either order and are idempotent.

**`slice:N` is the Nth page a divided top-level block has been on, written on the root of each piece**, with the custom property `--beltype-slice: N` delivered by one generated rule per distinct value (`[data-beltype~="slice:2"] { --beltype-slice: 2 }`) in a constructed sheet of the engine's own (`dressing.js`'s values sheet), never inline. **Two measured costs shaped it.** Changing an adopted sheet's rules invalidates the style of the whole document, which holds every page of the last presentation, so the rules for every number a presentation can write are delivered in one `replaceSync` before any piece is built (one `insertRule` per number, as the pieces were numbered, took the BGD manual's presentation from 140 ms to 258). And an unregistered custom property inherits, so a number that differs on the root of every piece differs on every element beneath it: the property is registered as an `<integer>` with `inherits: false` (the registry's `property` entry says so), which brought the presentation back to 140–150 ms. The price is that a descendant of a piece's root reads the initial `0`; the number is on the root. It is numbered from the page intervals, so a resumed presentation numbers the pieces on the pages it keeps again. **Not on the boxes nested inside a piece**: a nested box's first page needs the position of its first word, and a wordless box has none; the registry says so, and the number is an author hook, not a fact the measure may read (it reaches the presentation, not the feed).

**The truncation is a sheet, always on, in a layer named first** (`src/dressing.js`, with the rules themselves as text in `src/data-beltype.js` beside the words they are keyed on). The three words the sheet needs beyond the piece words were accepted on 2026-10-11: `wrapped` (the box wraps each fragment whole, `box-decoration-break: clone`; the engine decides per box because a selector cannot test the property), `adjoin` (the first-child chain after a cut between boxes: its block-start margin adjoins the cut, and it is not divided) and `away`. The rules are `!important`. The cascade reverses layer order for important declarations (css-cascade-5 §6.4.2): an important declaration in an earlier layer beats one in a later layer, and an unlayered important declaration loses to every layered one — so an `!important` rule in the FIRST layer beats an author's `!important` unlayered, layered, and in either source order. **The rules ride in the engine's provision `<style>`** (`seam/index.js`'s `headHtml`), the first sheet of the head after the addendum, because a layer's place in the order is where it is first named and an adopted sheet is after every document sheet. This was measured and it moved the design twice. The first draft adopted a constructed sheet and prepended a one-line `<style>` naming the layer: BelType's manual cost 3.5 % more (interleaved runs against the engine before the round, ten each: 3 145 ms against 3 286, the feed's layout 1 305 against 1 436) and BGD 4 %. Two things were in it. A layer named from script after the document has been styled invalidates every style and lays the document out again. And the same rules in a constructed sheet are slower than the same rules in a `<style>` element, layered or not and whatever they say (the rules unlayered and adopted, or layered and in the provision, both read as the engine did before; layered and adopted did not). So the provision carries the rules, and the adopted sheet with its layer-naming `<style>` (`ensureDressing`) is the FALLBACK, for a host that does not carry the provision — the essay's harness, a bare fixture — slower and the same in effect. Measured against Chromium's print on case 103: a plain rule, an `!important` rule, an `!important` rule in a layer and an inline style all end on the page Chromium ends them on.

Unlike the root's dressing sheet, **the words sheet is not taken out while the sources are measured** (`dress(off)` stays for the one sheet that has `break-before: auto !important` over every box of the root). It trims and hides, the measure feed is laid out under it (a divided box's truncated margin is part of the room a cut was decided against, as the inline styles were), and no source ever wears a word, so a sheet keyed on words cannot touch a source. `createMeasureContext` seats it, so it is present from the first feed.

**Numeric per-box inline values stay inline** (ruled): the §5.3 extension's padding, a blank shell's height, the painted shell's pull-up margin, pinned track widths and measured extents. **The extension padding is written `!important`**, inline: the sheet zeroes a cut-off box's bottom padding in a layer, the extension is that padding set to a number, and element-attached important declarations are the one thing that outranks a layer. (The first draft lost it: the extension came out zero and the cut line's room was wrong.)

**The "class starts with `__beltype-`" tests are a named set.** `fragments.js`' `putAway` and Caster's `isEngineMark` ask `ENGINE_MARKS` (`split`, `fixed`, `shell`, `break`, `fill`) — the set the prefix meant, to which `fragment` never belonged (a composed block's clone carried no class). The hot walkers do not split the attribute per call: `word-space.js`' `isLineBreak` tests the tag first and reads the word only of a `<br>`, and the Gauge asks the browser (`matches`, `querySelector` with `br[data-beltype~="break"]`).

**The line stamp's readers all go through a word reader.** The registry for the engine, and `common/src/data-beltype.js` for everyone else (the tab, Caster's Cicero adapter and core; *one grammar in common*, 2026-10-11 replaced the twins `editing-tools/assets/stamp.js` and Caster's reader, neither of which could import the engine), pinned equal to the registry by the root `test/data-beltype.test.js`. Nothing compares or sets the whole attribute: `restampFragments` replaces the `pos:` word of a standing copy and leaves its engine words, the keys (`composition-key.js`, `seam/client.js`) strip the one word and drop the attribute when nothing else is left in it, and Caster's pairing compares `posOf`. The old spelling was read and written in parallel for one commit and pruned in the next, inside the round.

**The native arm's guard is spelled with the word, and the original-box sibling lookup it left open is closed** (step 1's open item). The union's native arm keeps `:where(:not([data-beltype~="fragment"]))` before `:has(`; and the arm's own ARGUMENT now carries the same weightless guard after each compound a leading `+` or `~` reaches (and each further link of the sibling run), so an original shown whole that asks `section:has(~ section p.warn)` finds only originals among `<beltype-root>`'s children — the copies the pages made sit after every original in the root and were being found (case 102, red in the default mode before the fix). The inspector reads the guard back out (`authorSelectorOf`).

**Refused, and not to be mistaken for scope.** Caster's own reify classes (`caster-no-before` and the rest) wait for a Caster round. `hollow` and `:empty` are step 3. `data-ref-text` stays (CSS `attr()` reads it). The "one rule, one registry" refactor of reads, running heads and `:has()` is its own round.

## Where the code met the note

1. **The extension padding** (above): a layer's `!important` zero beat the inline number the §5.3 extension writes. Found by running the suite, fixed by writing the extension `!important` inline.
2. **The shell wrapper is exempt from the top rules.** The wrapper is `split` and not `start` (Caster reads a continuation by it), and an indent written on it would be INHERITED by the box it wraps, which the old inline writes never reached; the sheet's resumed-piece rules say `:not([data-beltype~="shell"])`.
3. **A layer needs a first sheet.** The ruling said the `!important` rule must beat an author's `!important`, and measured it does not today (case 103): the inline style loses. `root.js`'s dressing sheet was not layered at all, and an adopted sheet cannot be first however it is layered, so the rules are carried by the provision `<style>` that is first in the head; and, because the same rules adopted by script cost 3.5 % of a full run, the adopted sheet is only a fallback.
4. **What the sheet cannot beat, stated and not measured to occur**: an author's inline `style` with `!important` (element-attached important declarations outrank every layer), and an author's own cascade layer named before the engine's (an HTML-lane document whose own `<style>` precedes the engine's head fragment). The previous inline writes lost to both as well.
5. **Cached composed references are stale on purpose.** The composed differential prints the Compositor's hinted bytes through Chromium and digests them (`hintsOf`); `<br class="__beltype-break">` is now `<br data-beltype="break">`, so every cached composed reference reads as a different generator's and is rebuilt (`npm run gates:fresh`).
6. **An engine-inserted `br` or `span` now matches an author's `:not([class])`.** Today the Compositor's break and filler carried a class; after the fold they carry none, so `br:not([class])` or `span:not([class])` sees them. The trade is deliberate (ruled): the harm the fold removes is on the author's own boxes, and these elements are not the author's.

## Consequences

Numbers are in the CHANGELOG's entry for this round, and the three costs this round measured are above (the layer and where the rules live; the `--beltype-slice` property's registration and inheritance; the sheet rewritten once and not per number). The editing tools' preview patch road, the inspector (which never showed a union and still does not) and the follow/click source jump go on working through the stamp word; an edit to a stamped paragraph still takes the patch road (`packages/editing-tools/test/patch-plan.test.js`), and `restampFragments` leaves a copy's engine words alone.
