# The page carries its conditions

**Status: Decided 2026-10-21, Executed 2026-10-21.** A design round with Egildo, 2026-10-21, that began as a list of every generated-content function the engine handles and the mechanism each one has, asked what `string()` in the flow would need, and ended at one door for all of them. The measurements it rests on are probe P39 (`packages/essay/probes/publish.js`, nine cells, `probes/README.md`). The round that builds it is `.claude/plans/the-page-carries-its-conditions/plan.md`. Amended 2026-11-08 under Consequences: target counters stay spelled.

## Context

The engine answers a page fact through three doors. A margin box's `content` is resolved by the engine into a literal (`capture.js`'s `resolveContent`, spelling counters through `counter-styles.js`) and written into the cell (`chase.js`'s `setMarginBox`). An author's counter at the start of a page is written on the page's flow as `counter-reset` (`setCounters`), and the browser counts from there. A cross-reference's value is delivered as a custom property in an adopted sheet keyed on the attribute the function reads ([*a pointer is a read*](a-pointer-is-a-read.md)). A fourth kind, `:has()` and the slices, delivers words on copies. The ruling of 2026-10-09, *one rule, one registry* (`.claude/plans/cicero-optimisation/data-beltype.md`), named the shape they share, rewrite, answer, deliver, and left the refactor as its own round.

What convened this one is `string()` in the flow, which the checklist lists as not built and the pointer record defers to "the day this engine reads `string()` in the flow". It cannot use the cross-reference door: a `::before` reading `string(heading)` carries no attribute to key a rule on, which is the same wall `leader()` stands at. And it cannot use the margin door, which writes literals into cells the engine owns.

The round also found that `counter(page)` in the flow is kept by Chromium's parser and answered as an unreset counter, `0`, and nothing in the engine answers it.

## What the text says

- css-gcpm-3 §1.1.2, the `string()` function: it copies a named string "to the document, via the content property", with no restriction to margin boxes, and its four keywords are all questions about a page: `first` is "the first assignment on the page", `start` the entry value unless "the element is the first element on the page", `last` "the exit value", `first-except` empty "on the page where the value is assigned". So a flow `string()` is a per-page value: every site on one page reads the same one.
- css-page-3 §6.1: "A counter named page is automatically created and incremented by 1 on every page of the document", and `pages` is the total; a page counter is a counter, with every counter style.
- css-page-3 §6: margin boxes inherit from the page context, and the page context does not inherit into the document. `chase.js` keeps this with a selector that cannot match, not a wall; P39f measures that a `color` on the host does reach the slotted paragraphs.
- css-scoping: names declared in an outer tree are visible in an inner tree; P39h measures an author's `@counter-style` applying inside the page's shadow.

## Decision

**The page carries its conditions as declarations on its own host, and everything the page holds reads them through the cascade. A number is a counter the host resets; a text is a custom property the host sets; the browser spells every counter.** Four rulings.

1. **The host resets the page counters beside the author's.** `setCounters` already writes the page's start state as `counter-reset` so the browser counts inside the page; it gains `page N` and `pages T`, and the reset moves onto the **host**, since P39g measures that a reset on the flow reaches the paragraphs and not the margin cells. `counter(page)` and `counter(pages)` are then native wherever they stand: in a margin cell, in a flow `::before`, in any style the browser knows, an author's `@counter-style` included. Until the run is complete `pages` stands at its reservation, as it does today.
2. **A margin box's `content` is transliterated, never resolved.** The author's declaration goes into the page's shadow sheet onto the cell's `::before`, through the same dress that already carries the page context's `color`, and the browser evaluates it against the host's counters. `resolveContent` stops spelling values and `counter-styles.js` leaves the margin path. Whether the box exists (css-page-3 §5.2, *a margin box exists by its content*) is read from the cell's computed `content`. `element()` keeps the slot: a node is not a value, and the slot is the one place a read and a slot meet (the pointer record's own line).
3. **A named string is a custom property on the host, per page and per keyword.** `--beltype-string-<name>-<which>`, unregistered or registered `inherits: true` (P39d: registration decides the reach). A margin cell reads it transliterated; a flow site reads it through the rewrite branch the three target functions already have, because Chromium drops every flow `string()` form at parse (P39e). The content-list evaluation at the assigning element and the four keyword answers over the page's interval stay exactly where they are, in `document-state.js` and the driver's `closes`. A flow site is a layout read, local, reserved as the `var()` fallback `""` during the run, checked after delivery in the loop the pointer record built: the measure clone has no page, so the fallback is the reservation by construction.
4. **The published names are the engine's reserved ones, and nothing else goes on the host.** The firewall is a selector that cannot match (P39f): a page-context `color` on the host would reach every paragraph, and that stays refused. What the host carries is `counter-reset` and `--beltype-*`, which no author sheet reads by accident.

**What this is.** Three scopes, and the cascade carries each down: a fact about **the page** sits on the page host; a fact about **the document** (`pages`) sits with it, the same on every host; a fact about **a target** stays in the adopted sheet keyed on the attribute the function reads. The registry ruling's three steps are unchanged; what collapses is the deliver step, from three doors to one host and one sheet.

**Left where it is, with the measurement that would move it.** The per-target reads could go native the same way: the delivery sheet would set `counter-reset: --beltype-read-N <page>` on the pseudo and the rewrite would turn `target-counter(…, page, lower-roman)` into `counter(--beltype-read-N, lower-roman)`, and then the engine would spell no number anywhere. P39i measures that it works, and measures its price: a later `counter-reset` on the same pseudo, an author's own, replaces the engine's silently and the read prints `0`. Two custom properties never collide. The half is not taken in this round; it waits on Egildo's ruling with that price in front of it, and `counter-styles.js` keeps its one caller, the reads' text, until then.

**Refused.** A key on the author's elements for a per-site string (a word on an original, Paged.js's attribute stamp): the value is per page, so no site needs an identity. A path selector as a key: a continuation's child counts differ from its original's. A second encoding for the host: the page context refuses custom properties at parse, which is why the string-literal encoding exists, but the host is the engine's element and its inline declarations are not parsed from the author's sheet; nothing new is spelled.

## Consequences

- **Displaced**: `resolveContent`'s value spelling and `setMarginBox`'s string case; `counter-styles.js`'s margin callers; the per-page literal for `pages`. `counter-styles.js` stays for the reads' text delivery.
- **Owed**: the flow `string()` rewrite branch and its encoding name, in `gcpm-encoding.js`; the host's `publish` beside `setCounters`; the check loop finding flow sites that read a page fact (`string()` through its property prefix, `counter(page)` through the capture's `content` walk); the cell's existence read from its computed `content`; three cases next door, red first; the checklist rows for `string()`, `counter(page)` in the flow and `@counter-style`.
- **Not owed here**: the per-target native half (its price is P39i's); `leader()`, whose scope is the line; `element()` in the flow; footnotes.
- **Where the content lives**: the mechanism in `chase.js` and `root.js`, the names in `gcpm-encoding.js`, the status in the checklist, the measurements in P39, the story in the CHANGELOG under this date.

**Amended 2026-11-08: target counters stay spelled, and the native half is declined.** The quick-rulings row *registry-per-target-half* asked whether the half of the registry that spells a target counter's value into the document could give way to the platform's own generated content. Egildo ruled to keep spelling, and had second thoughts on performance the same day, so the cost was measured before the ruling stood: on the manual the spelling is 5 microseconds of the reads' 272 ms, and the ruling stands. The native half is declined by *the conservation of words* (Caster's DESIGN.md S61): every rendered word must be claimed by the source it came from, and a value the platform generates in a pseudo-element is a word with no source node to claim it, so a printer on this seam could not print it. The measurement found a row of its own, not ruled here: the counter walk runs twice per load.
