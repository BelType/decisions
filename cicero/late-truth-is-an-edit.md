# Late truth is an edit

**Status: Decided 2026-10-13, Executed 2026-10-13.** The first build of the live-values round (`.claude/plans/live-values/design.md` at the repository root, stage 1). Written for a Sonnet to build from; the predictions are frozen before anything runs. Amended 2026-11-08 under Consequences: a picture is a signal only where it moved the box.

## Context

The tablet states late-arriving truth as one phenomenon with one machinery — fonts that load, images that size themselves, forward references, content whose geometry firms up after the first measurement: *void entries from the last entry before the changed box, rebuild forward* — and the architecture's **Late-arriving truth** section gives the driver's voice: one rim at the system's edge, every signal the same act, `ledger.voidFrom(box)`, then the forward build resumes. Since 2026-09-18 the section carries a status line: the rim is designed and unbuilt, `voidFrom` has a unit test and no production caller, and images are awaited at intake as a stand-in ([*images are awaited at intake*](images-are-awaited-at-intake.md)).

Two later rounds built the machinery under another name. [*The run resumes from an entry*](the-run-resumes-from-an-entry.md) made a run restart one page before the page holding an edited box and converge where the keys are equal again — which is `voidFrom`'s act at the page grain, with the one clause the position-grain verb did not know (a cut reads the boxes it pushed to the next page, so the restart is one page earlier than the holder). [*The pages are cut as far as they are asked*](the-pages-are-cut-as-far-as-they-are-asked.md) made the run holdable and gave an edit while the document is incomplete its own path. What is still missing is the rim itself: nothing in the engine or its seam subscribes to the signals, so a custom element defined after the run keeps the size it had undefined, a font that finishes after the run leaves every line measured in its fallback, and an image whose source changes after the run is never measured again. Stage 0 of the live-values round measured the ground (the design note's *Measured 2026-10-13*): the manual's three missing pages do not reproduce today, so the rim has no standing victim to point at; a lazy image inside a parked original never loads, so the intake's stated limit for `loading="lazy"` is a hole and not a limit; `hidden` and `itemprop` hold through the intake and the copies.

**Rulings the design note carries (Egildo, 2026-10-13)** and this record builds under: known signals announce themselves and need no observer; what is watched beyond them is the known-late kinds plus what is marked `watch` (stage 6, not this build); **the host decides when to act on a signal, and a host that says nothing gets the immediate default**; pagination cuts on the settled state; pointer state never reflows a page; the copies stay; writers that are not the store are patched (stage 6).

## Decision

**One. A late-arriving signal about a box is handled exactly as an edit at that box.** The rim turns a signal into `run({ resumeAt: box })`: the resumable run restarts one page before the page holding the box, re-measures from there and stops where the keys converge. There is no second invalidation machinery. `Ledger.voidFrom` is therefore answered in spirit by the driver's page-grain truncation; the build decides its letter — it becomes the truncation the driver calls if the two agree on every case, or it is deleted with its unit test, because a verb that is tested and never called is a green nobody can name a reason for. The build reports which.

**Two. A signal about the conditions is a whole run.** A font that finishes loading after the run is not a box's fact but a condition of every box (*a break decision is valid only under render-identical conditions*; the resumable run's own key says a changed font dirties page one). `document.fonts`' `loadingdone` after the intake therefore asks for `run()` with no `resumeAt`, once, after any run in flight has ended.

**Three. The rim is a subscription at the seam, taken at intake, on the originals.** `seam/rim.js`, called by `seam/client.js` when the intake is taken and released when the frame lets the run go. It subscribes, on the top-level boxes the intake took:

- every `<img>` that is not `complete`: `load` and `error`, once, naming the top-level box that holds it (today the intake awaits them all, so the listener is reached only by an image that becomes pending later — a changed `src`; it is wired now because the store's write to an image field is this exact event);
- every element whose name has a dash and is not yet defined: `customElements.whenDefined(name)`, then one animation frame, naming every top-level box holding one;
- `document.fonts`, `loadingdone`: the conditions.

Nothing is observed by size in this build (the `ResizeObserver` and the `MutationObserver` are stage 6, under the ruling on the known-late kinds and `watch`).

**Four. The hand-off is one cancelable event, and the default action is the resume.** A signal dispatches `CustomEvent('beltype:change', { bubbles: true, cancelable: true, detail: { kind, boxes } })` on the document, `kind` one of `image`, `element`, `font`, `boxes` the top-level boxes in document order (empty for `font`). A host that calls `preventDefault()` has taken the pace: nothing happens until it calls `run()` itself. A host that does nothing gets the immediate default: signals are coalesced over one animation frame, then the engine runs one `run({ resumeAt })` per box, earliest first, one at a time (convergence is believed past ONE edited box — build four's finding — so several boxes are several runs), or one whole `run()` where the batch holds a `font`. A signal that arrives while a run is in flight waits for it; a signal while the run is stopped at a page resumes within the pages cut, as an edit does. The event is the same one the live-values store will dispatch for its writes (`kind: 'store'`, stage 2), so the engine learns one name for every late truth and the host cancels one event to own the pace — the platform's own form for *the host decides*.

**Five. The intake ignores `loading="lazy"`.** `measure.js`'s `awaitImages` sets such an image eager and awaits it like the others, and the warning that counted the skipped ones goes. Measured 2026-10-13: a lazy image with no box never issues its request, and a parked original has no box; print has no viewport, so there is nothing for lazy loading to optimise. The stand-in otherwise stays for this build: an image in flight at intake is still awaited before the first measure, because retiring the await trades a known-good first paint for one resume per image, and that trade is a measurement this build owes (below), not a ruling it has.

**Refused.** A second event name for the engine's own signals beside the store's. A time budget or a debounce longer than a frame in the engine (the pace is the host's). Invalidating at the position grain with a separate forward build (the resumable run is that build). Observing sizes in this build.

## Predictions

Frozen on write.

1. **The proof is red first.** `packages/essay/test/rim.test.js`, both modes, on a document that holds a custom element defined 300 ms after load (rendering 240 px tall once defined), a font face loaded by script 300 ms after load and added to `document.fonts` (the body set in it, so every line rewraps), and a lazy image: before the build, the Ledger after the signals differs from the Ledger of a run on the same document with everything ready before the first run — in page count or in cut positions. BREAK if the two are already equal, which would mean the document does not put the question.
2. **After the build the two Ledgers are byte-equal**, in both modes, and `complete` is true; the signals cost one whole run (the font) and one resume (the element), in either order, and never more. The lazy image is measured at its real height on the first run.
3. **A host that cancels the event gets no resume**: the Ledger stays the first run's until the host calls `run()` itself, and then equals prediction 2's.
4. **A signal while the run is stopped at a page** (`until: 2`) resumes within the pages cut and does not complete the document; carrying on to the end then gives the Ledger of prediction 2.
5. **No battery record moves.** The corpus and the cases hold no late custom element and no script-loaded font, and the one `src/` change (lazy made eager) reaches a document only where it writes `loading="lazy"`, which none does. BREAK on any record moving.

## Verdict

Built 2026-10-13 on `round/live-values`; the proof is `packages/essay/test/rim.test.js` (ten tests, both modes, stable across three runs including two beside the whole essay suite), the battery 26 of 26 pinned to `881bb15`.

1. **The proof is red first — held, with one document that had to be made deeper.** Against the unbuilt rim the committed test failed on the Ledger after the signals (b), on the event count (c, d: the rim never spoke) and on the lazy image (e). The honesty guard (a) held from the first run: the LATE first run and the READY-FIRST run both cut 21 pages in both modes, and their Ledgers differ in cut positions — which is why the prediction says *page count or cut positions*. The lazy image did NOT go red at first: placed 30 paragraphs down it sat 1 200 px into the unpaged flow, inside Chromium's lazy distance, and loaded by itself; the document was made 360 px wide on screen and the picture put 40 paragraphs down (about 4 800 px) before the claim failed for the reason the record names.
2. **After the build the two Ledgers are byte-equal — held, both modes, `complete`.** The cost is exactly one resume and one whole run beyond the host's own first run: the element is `run({ resumeAt })` with `resumed { from: 1, to: 20, shift: 2, converged: true, kept: 3 }` (23 pages for a moment, the face not yet in), the font is a whole run that returns the document to 21 pages. Measured on this machine: default mode whole run 33 ms, resume 17 ms, font whole run 16 ms; composed 108 ms, 25 ms and 95 ms. The lazy image is measured at its real height on the first run: the Ledger of the lazy document equals the eager one, and both differ from the document without the picture.
3. **A host that cancels the event gets no resume — held, both modes.** Both events are announced, no run follows, the Ledger stays the first run's byte for byte, and the host's own `run()` gives prediction 2's Ledger.
4. **A signal while the run is stopped at a page — held, both modes.** With `until: 2` the element resumes within the two pages cut, the font is a whole run held to the same two pages, `complete` stays false throughout, and carrying on gives prediction 2's Ledger.
5. **No battery record moves — held.** 26 gates, 26 ok, 0 failed, 18.5 min: native `163 agree, 18 legal-divergence, 7 theirs-illegal, 11 unclassified, 1 reference-invalid`, composed-v1 `89/8/3`, composed-v2 `86/10/4`, v3-native `43/5/1/1`, v3-composed `28/1/1`, v4 `43/4/2/1`, view-native 50, view-composed 40, view-v3 30 view-agree; acceptance, conservation, the narrated cases, every probe, the browser suites (172) and the engine suite (307) green. Only `RESULTS.md`'s pin and `gates/PIN.json` moved, which is what a complete run rewrites.

**What the record did not foresee.**

- **A font was not a condition of the run.** `conditionsKey` (the viewport, the pixel ratio, the colour scheme, the sheets' text) had no word for a face that finished loading, so a resume would have been believed across one, and — worse, in the composed mode — a whole run after a late face would have reused every paragraph composed at the fallback's widths, from the cache. The record's Decision two says a changed font dirties page one; the seam did not know it. The count of `loadingdone` events now rides in the key as the number the run BEGAN under (read after the intake, which waits for the faces the document asks for; read at the end it would have hidden a face that arrived during the run). That is why `describeConditions` in `src/driver.js` gained one clause and `test/driver.test.js` one assertion — a second `src/` change the Consequences did not list, comment-honest and message-only: the arithmetic never reads the string.
- **The rim must start after the images are awaited.** Started at the intake it subscribed to a lazy image the driver then made eager, and heard its first load as a late signal: a resume on every document with a lazy picture. The seam now awaits the pictures itself, at the intake, before the rim starts (the driver's await finds nothing pending).
- **The listener the record names does not hear a changed `src`.** `load`/`error` once on the images that are not `complete` leaves a picture that was complete at the intake deaf, which is exactly the case the record says the listener is for. The rim listens in the capture phase on each top-level box instead (`load` and `error` do not bubble), one pair of listeners a box, and `add(box)` seats a replaced box after `patch`.
- **A timer is not a staging.** 300 ms after load was shorter than the first run once the whole essay suite ran beside it, and the LATE reading stopped being late. The test brings the element and then the face itself, each after the rim has gone quiet.
- **Two small things in other suites.** `progressive.test.js` counts how many times the engine asks the document for `document.fonts` (the second ask is where it makes a run throw), so the rim takes the face set the client kept at load; and the undo of a failed first run stops the rim.
- **`voidFrom` was deleted, not called.** The driver's truncation is page-grain, anchored on the main flow's address through `holderPage`, with the dangling-address, whole-box and changed-read clauses around it; `voidFrom` is position-grain over the earliest of ALL an entry's paths. They disagree wherever a flow is carried, so the swap was not one obvious line, and the verb, its four unit tests and the sentences calling it the machinery went.
- **Owed, unchanged from the Consequences, and now sharper:** a face that first loads during the first run's own measure (or in a margin box's text) is a `loadingdone` the rim answers with one more whole run. It is bounded — the second run asks for nothing new — and no document in the battery meets it; the manual with the first-run image await off is still the measurement that decides the stand-in. *(The margin-box half is closed by the amendment below, 2026-10-13: the one that remains owed is a face first loaded during the first run's own measure, which is the stand-in's question.)*

**Amendment, 2026-10-13: the margin-box face is requested before the first cut, and a rebuilt face is not news.** `packages/essay/test/furniture-face.test.js`, both modes: a body set in a generic family, a folio set in `"Late Folio"` declared by `@font-face` in the document and served by the venue, used by nothing else.

- **The gap was real and measured.** With a face rebuild filtered (see the next point) so the first load could be counted at all, the folio-only document cost TWO runs and one `font` event on every first load, default and composed; the same document with the face preloaded by the host cost one. The ready-first Ledger and the two-run Ledger were byte-equal (the face changes no cut), so the cost was one wasted whole run and a visible relayout, as predicted.
- **What the case found first, and the record did not foresee: a rebuilt face is not a new fact.** Before the gap could be counted, the document ran itself over and over — 38 runs in the default case's window, 21 composed, 361 in six seconds when left alone — and the same loop ran for a face the FLOW uses, so it was not the gap. Chromium rebuilds the `FontFace` objects of a document's own `@font-face` rules whenever the active stylesheets change by anything but an append, and every presentation removes and re-adds the press `<style>` (`root.js`); the rebuilt face loads again from the memory cache and fires `loadingdone`, which the rim heard as a condition change, whose whole run presented again and rebuilt the face again. It needs a webfont in a document `<style>` or a linked sheet that something lays out, and a margin box (without one the document did not loop, though it still took one spurious extra load), and neither the rim test (its face is added with `document.fonts.add`, which no stylesheet change rebuilds) nor the battery (no `@font-face` in a document the seam runs) had one. `seam/rim.js`'s `bringsNewFace` now decides whether a `loadingdone` is news: a face is news the first time its descriptor (family, style, weight, stretch, unicode range, variant, feature settings) is seen, the faces already loaded when the module runs are known from the start (`knowLoadedFaces`), and both listeners — the client's epoch and the rim's signal — ask the same memoised verdict per event. A changed `src` is a changed stylesheet, already in the run's key, so nothing real is hidden. The `seam/` is the only place changed for it.
- **What was built for the gap.** `capture.js`'s `readGeometryTable` returns `furnitureFaces` beside `pageFor`: one `FontFaceSet.load()` argument per family, weight and style the `@page` rules name (the page context's, and each margin box's own over it; `var()` and the global keywords skipped), never every declared face. `measure.js`'s `awaitFonts(doc, faces)` loads them (font preloading, by its platform name) and then awaits `fonts.ready`. It is called from the seam's intake right after the table is read, BEFORE the rim exists (the first attempt called it only from the driver, inside the run, and the rim heard the face arrive there as a late condition: still two runs), and again by the driver, where it finds nothing pending and serves a host that does not enter through the seam. A running element needed nothing: it is laid out in the flow at intake, so the forced layout already requests its face (measured with the preload disabled: one run).
- **Held.** (b) one run, no `font` event, and the face's `loadingdone` before the first run's `cicero:images` phase ended (the last thing the driver does before the first geometry), both modes; (c) the Ledger equals a ready-first run's, byte for byte; (d) a face used by flow text costs one run before and after, both modes.
- **No battery record moves.** 26 gates, 26 ok, 0 failed, 16.0 min, pinned to `f6abb2f`: native `163 agree, 18 legal-divergence, 7 theirs-illegal, 11 unclassified, 1 reference-invalid`, composed-v1 `89/8/3`, composed-v2 `86/10/4`, v3-native `43/5/1/1`, v3-composed `28/1/1`, v4 `43/4/2/1`, view-native 50, view-composed 40, view-v3 30 view-agree.

**Amendment, 2026-10-13: the store's kind, and a patched box releases what it held.** `packages/essay/test/rim.test.js`, both modes.

- **`kind: 'store'` has the engine's default action.** Decision four said the store's event is the same one and the host cancels it to own the pace; what it did not say is who answers it when nobody cancels, and the rim answered only its own signals (`onSignal` ran after the rim's own dispatch), so a `beltype:change` dispatched by the live-values module resumed nothing and a host had to stand a listener in to call `run()` itself. `rim.js` now listens for the event on the document, ignores the ones the rim dispatched itself (a `WeakSet` of its own events, not a test on `kind`, so a host that dispatches `image` or `font` on its own is answered too), waits ONE animation frame and, if the event is not `defaultPrevented`, hands `{ kind, boxes }` to the same `onSignal` as the rim's own, which is the coalescing, the one resume per box earliest first and the waiting for a live run. **Why the frame:** the module's default action writes the fields synchronously right after `dispatchEvent` returns un-cancelled, so an answer at the dispatch would measure the old values; the frame comes after that write and before any paint. A `detail.boxes` entry that is not a top-level original (a detached element, a nested one) is skipped, as a box that left the document already was, and an event left naming no box resumes nothing. The listener is installed with the rim at intake and removed by `stop()`. The kind union gains `'store'`.
- **Measured.** Three fields in three paragraphs far apart, 60 words written into each after the event: before the amendment the Ledger stayed the first run's and no run followed; after it three resumes ran, earliest first, and the Ledger equals a whole run over the same DOM, default and composed. A cancelled event resumes nothing; an event naming a detached element resumes nothing and throws nothing.
- **`rim.add` leaked.** `patch` re-calls `add` for a box it patched inside (the top-level box stays the same element) and for a box it replaced, and each call stacked another capturing pair of `load` and `error` listeners with nothing released. Measured: one image load announced twice after one patch, three times after two. `add(box, replaced)` now keeps a `Map<box, release>` and releases the replaced box's and the box's own before seating the new pair; `stop()` releases all of them.
- No `src/` change; the battery is not moved by it and was not re-run.

**Amended 2026-11-08: a picture's arrival is a signal only where it moved the box.** The measurement this record's Consequences left owed was taken on 2026-11-08, on a 59-page document with 60 images served late rather than on the manual: with the first-run await off the rim heard 60 loads and resumed 59 times, and no resume moved a cut, since every image had its size declared. Egildo ruled the same day ([*the first run waits for no picture*](the-first-run-waits-for-no-picture.md)): the rim judges a `load` or an `error` when the runs have ended, against the height the last run measured for the box, and a box drawn as itself at that height is no signal. A box the arrival grew or shrank resumes as before, one resume at the box. Decision four's default action is otherwise unchanged; the kind union is unchanged; the clone await inside a slice is outside this record and stays ([`seam/rim.ts`](https://codeberg.org/BelType/cicero/src/commit/b08c06ddd43655b2a7e4f7b2b1644ac0b9e49c5f/seam/rim.ts)).
