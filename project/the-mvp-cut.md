# The MVP cut

**Status: Decided 2026-09-02.** Closes the BelType-on-Cascata round alongside [cascata-owns-the-cascade](cascata-owns-the-cascade.md), [a venue is a schema](a-venue-is-a-schema.md), [run options are flags](run-options-are-flags.md) and [the keyscope is not the cascade](the-keyscope-is-not-the-cascade.md).

## Context

The three entries above delete most of what `packages/core` and `packages/cli` used to do to resolve a configuration, and the round's aim was never to migrate that machinery key for key — it was, in `VISION.md`'s own trajectory, a still more immediate editing experience, reached by returning one value from core so that the next round is a scheduling problem, not an architectural one. Deleting the cascade machinery makes several of its consumers — the exporter, the fingerprint, the vendorer, the scaffolder, the home config rung — either incoherent or simply no longer load-bearing for the one job that remains. `TABLET.md`'s "deferred, not abandoned" sets the bar for cutting them: its reasoning and shape are recorded precisely enough that picking it back up doesn't mean rediscovering it. This entry is that record for everything the round cut, and — because it must stand alone in the repository the way every decision record does — it carries the reinstatement reasoning itself rather than pointing at a plan document outside it.

## Decision

**The MVP renders documents: preview, edit, PDF, under all three engines. Everything else is cut, to be grown back deliberately rather than migrated by inertia.**

| cut | today | in the MVP |
|---|---|---|
| `beltype build` (dist) | `packages/cli/src/exporter.js` | deleted; `build` keeps only `--pdf` |
| the fingerprint | `packages/core/src/fingerprint.js` | deleted with the exporter |
| `beltype vendor` | `packages/cli/src/vendorer.js` | deleted |
| `beltype init` | `packages/cli/src/scaffold.js`, `packages/cli/templates/`, `--skill` | deleted; the starters' venue configs survive as test fixtures |
| the home rung | `~/.config/beltype/config.yaml` | deleted; its keys are flags now |
| molds, schema subset, requires, territory, the two spaces, mounts | `config-schema.js`, most of `config-loader.js` | deleted; Cascata and the Linker answer |
| `cover` | `renderCover`, `.beltype-cover`, `@page cover` | deleted; a directive plus author CSS does it |

**Proposed for the cut and ruled against: `plugins` and `directives.*.render`.** The draft cut both, along with `plugin-loader.js` and the provider's `loadModule` that serve them. Building the schema found four live users a `{ tag, className }` directive cannot express: `packages/essay/book`'s `embed-proof`, `embed-file` and `embed-corpus`, each computing HTML from the repository at build time, and the manual starter's `finance-card`. The book would have stopped building, and the reinstatement note would have had to carry a mechanism the repository was using on the day it was written — which is not a cut, it is a debt. Ruled 2026-09-03: the render mechanism stays, and `plugins` stays with it, because the loader is the same door and cutting the key while keeping its loader buys nothing.

**The PDF path changes shape rather than surviving unchanged**: `build --pdf` starts the dev server in-process, opens the document's own URL in headless Chromium, and prints from there; `renderPdf` takes a URL, not a served `dist/` directory. There is no `dist/` in the MVP at all — the coupling between print and export was always that Paged.js can't fetch linked stylesheets over `file://`, never a real dependency between the two ideas, and severing it is the simpler shape rather than a temporary one.

**Kept in core on purpose, because the cut is about what a rendering path needs and both of these are load-bearing for it still**: `packages/core/src/closure.js` survives because it has two live consumers after the cut — the editing tools' Resources panel and the dresser — and because it is pure, reading text only and listing binaries unopened; nothing about deleting the config cascade touches what the closure computes at the handoff seam. `line-map.js` and `linker.js` stay for the same reason: the line-map is `packages/editing-tools`' one customer for preview-to-source navigation, and the linker's root-absolute rewrite algebra is what [cascata-owns-the-cascade](cascata-owns-the-cascade.md) explicitly leaves outside Cascata's remit.

## Consequences — the reinstatement

Five things wait behind this cut, in the order Egildo asked for them, each with what has to be true before it returns.

**1. Materialize and serialize — first, directly after this round lands.** The resolved document the belt hands off admits exactly two realizations: `serialize(rd)` produces ordinary standalone HTML with `<link>`s, and `materialize(rd, realm)` constructs and adopts every sheet live in a browser realm — the shape `packages/editing-tools/assets/dresser.js` already prototypes, sheet construction in the target realm's own globals, relative refs rewritten at construction, imported sheets seated before their importers. `Shell.wrap`/`Shell.splice` become `serialize()`; `materialize()` is new. **One correction the first draft of this cut got wrong and this record fixes before it ships**: `@layer beltype` does not go. CSS sorts by origin and importance before it sorts by specificity or order, so between two *unlayered* sheets specificity wins before order — an addendum rule like `article > section > h2` would beat a plain author `h2 {}` the moment the layer disappeared, a regression for every author who has ever relied on it. The design to build instead keeps today's three-layer shape and widens it by one: `@layer reset, beltype;` declared once and first, `reset` inside `@layer reset`, `mechanics` unlayered, `addendum` inside `@layer beltype`, an `engine` layer decided per engine at its own seam, and `author` unlayered and last as always. Before this returns, four measurements have to hold: adopted sheets seat after every document sheet in the target Chromium (re-confirm the dresser's own prior measurement); Paged.js is expected to *fail* to take adopted sheets, since its polyfill preprocesses stylesheet text fetched by URL and a constructed sheet has none — if it fails, Paged.js takes an honest degraded seat under the marginalization doctrine, serialized rather than materialized, and that is not a defect to fix; Cicero needs its `document.styleSheets` walk widened by one line to see adopted sheets, its own round behind `packages/essay`'s battery; and a fixture pair has to prove a plain author rule beats every addendum rule, and loses fairly to a higher-specificity mechanics rule, under all three engines.

**2. Cascata in the tab — second.** The refactor runs Cascata in Node on both backbones; the browser tab that `packages/editing-tools` hands live edits to does not run the cascade stage itself yet, only the belt, link, and assemble stages. Two obstacles are measured, not assumed: Cascata's `hashBytes` calls `node:crypto`'s synchronous `createHash`, where the browser only offers `crypto.subtle.digest`, asynchronously — the fix is either making `hashBytes` itself async, the road `packages/core/src/fingerprint.js` already walked, or moving `hash(bytes)` onto Cascata's own Host seam, which fits its capability-boundary grain exactly; either is Cascata-side and Egildo's call, not this round's. And the `yaml` package is CommonJS with an ESM browser build reached only through the `browser` export condition, which BelType's import-map generator does not yet resolve. Cascata's other Node imports — `node:path`, `os.homedir` in a few resolution modules — are pure algebra the tab already shims, so they are not blockers. Once both are closed, `packages/editing-tools`' server stops owning the cascade; the tab runs `load()` through its own HTTP host, draft-first, and `config-changed` survives unchanged in meaning — a document in the read-set changed — because that was never about which process ran the cascade. *(Taken 2026-09-04: the tab runs the cascade through its own HTTP host and the server never calls `resolveConfig` — [the generation stays in the tab](the-generation-stays-in-the-tab.md); Cascata stopped reaching for `node:crypto` in its v1.5, egildo/cascata#1. `config-changed` went with the server-side cascade.)*

**3. Export, fingerprint, vendoring, init — return only once each has a customer again, not on a schedule.** The exporter returns when the site engine's deployable output is wanted again; when it does, the closure stays the *only* authority on what ships, and the old `copyVendored` substring-search special case for `vendor/fonts` must not come back — vendor assets become ordinary closure entries like everything else. The fingerprint returns bundled with the exporter, since an artifact was always its only customer, and the same two rules survive unchanged: never hash the resolved config (absolute paths make one document fingerprint differently on two machines), never widen the claim to output bytes (Chromium makes that unachievable). `beltype vendor` returns, if it does, as an operator convenience rather than a build-time refusal — trust-through-verification's direction, argued for vendoring specifically rather than inherited from the general doctrine. `beltype init` returns reshaped by [a venue is a schema](a-venue-is-a-schema.md): a starter is a schema a new document names, so `init` degrades to "write a frontmatter naming one" — if it returns at all, since that reduction may leave nothing for a dedicated command to do. The `~/.config/beltype` rung does not return; every key it held was operator territory, and operator territory is the CLI's whole story now, per [run options are flags](run-options-are-flags.md).

**4. The PDF path stays URL-based even after export returns.** `dist/` and print were coupled only because Paged.js cannot fetch stylesheets over `file://`; printing from the dev server's own URL is the simpler shape regardless of whether an exportable `dist/` exists again, and there is no argument in this cut, or expected after it, for recoupling them.

**5. Five findings from the 2026-09-02 over-engineering audit, parked behind the cut rather than fixed inside it**, because fixing them was not what this round was for: the WebSocket reload channel is one-directional in practice — every message travels server to client, nothing anywhere listens for a client message — and a single `EventSource` route would replace it and drop `ws` from two packages; `packages/editing-tools/src/import-map.js` hand-lists twelve transitive CodeMirror packages that a walk of `node_modules` dependency graphs would derive instead; `packages/editing-tools/src/watcher.js` was an 88-line copy of the CLI's own watcher, kept separate only to avoid an inter-package import that `beltype edit`'s existing lazy `import()` of editing-tools already makes safe (closed 2026-09-23: both watchers are gone, [Provenance watches the files](provenance-watches-the-files.md)); `packages/common/src/logger.js` hand-rolls ANSI colour codes that `util.styleText` replaces once Node 20 is the floor, which this round sets; and `default-plugins.js` registers both `remark-toc` and BelType's own `@toc` at-rule, redundant absent a customer for the former. None of these blocks the MVP; all five are real, and are recorded here so a future session finds them rather than rediscovering them by reading the same files again.
