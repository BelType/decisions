# Provenance watches the files

**Status: Decided 2026-09-23, Executed 2026-09-23.** Recorded in [`packages/editing-tools/DESIGN.md`](https://github.com/egildo/beltype/blob/42b348b547d269a217a7f193042fe216386a4650/packages/editing-tools/DESIGN.md) as proposition 51. Its watch sets — the CLI's and the editing server's — were superseded the next day by [The render reads through the session](the-render-reads-through-the-session.md): both now come from Provenance read passes, and the regression below is closed in both. The change feed itself, its file-level watching and its byte-level notion of a change stand.

## Context

BelType had two file watchers, and both were chokidar: `packages/cli/src/watcher.js` for the dev server and a near-copy, `packages/editing-tools/src/watcher.js`, for the editing server. Each watched DIRECTORIES — the venue, the document's folder and every `rewrites` target, recursively — and grew add-only as each render's read-set arrived, because a chapter included from outside every watched directory would otherwise change with nothing noticing. The copy's own header argued that forty lines of wiring were cheaper than a base class.

Provenance is the author's library for exactly this knowledge: for one rendered document, every source involved, how the sources depend on one another, and a host that watches them. Its kernel was published as `@egildo/provenance@0.1.0` on 2026-09-23, on GitHub Packages beside Cascata; the round landed on 0.2.0, published the next day, which changes nothing the feed uses. A session holds roots, every source reachable from them and a host that watches them, and it reports what changed. With no handlers every root is a leaf — nothing parsed, no edge followed — which is all a watcher needs.

## Decision

**One change feed, `packages/cli/src/change-feed.js`, holds one Provenance session and is the only watcher in BelType.** The CLI and the editing server both use it; the editing tools already depended on `cli`. Both `watcher.js` files are deleted, and `chokidar` leaves both packages.

**The feed watches FILES, and the set is whole every time.** The caller hands over every absolute path it wants watched and the feed applies the difference as `addRoot` and `removeRoot`, so what leaves a render stops being watched — which the add-only watcher never managed.

- The CLI's set, recomputed after every build (success or overlay): the target; the render's `readSet`, both the last good render's and whatever the build in hand read before it failed, so a chapter that just broke the build stays watched; every closure entry's `source` and its `beside` entries, which the Linker already mapped to files, so no alias law is restated; the cascade's config files; and the venue probe's two candidates.
- The editing server's set, recomputed on every posted tree: the tree's `readSet`, the source of each text-kind resource, and the venue probe's two candidates, with the target standing for the read-set before the first tree. A desk standing on a folder opens no feed until a document is chosen; `open` closes the old one.
- *(Superseded 2026-09-24: the passes record the probe's misses in the CLI, and `venueCandidates` is deleted with its last caller.)* **The venue probe's candidates are core's.** `venueCandidates(targetDir, cwd)` is exported from `cascade.js` beside `findVenue`, which now iterates the same rule, so a watcher never restates where a venue may stand. Watching them is what makes CREATING a `beltype.config.yaml` noticed; in the CLI a batch naming one reloads the cascade, as a batch naming a config the cascade read always did.

**Only `changed` is reported.** With no edges, `added` and `removed` are only ever the feed's own `addRoot` and `removeRoot` echoing back; reporting them would turn every new watch set into the rebuild it came from.

**A change is a change of bytes.** Provenance versions a source by its SHA-256, so re-saving identical text reports nothing and rebuilds nothing. Its Node host watches each file's parent directory filtered by basename, debounced 300 ms like the old watchers, so an editor's temp-write-then-rename save is one change and the temp file is nobody's — which is also why the editing server's own atomic write still produces exactly one `changed`. A missing file is watched anyway and reports when it appears.

**The feed hands back the caller's spelling.** Provenance keys a source by its canonical location (a realpath: `/var/…` reads `/private/var/…` on macOS), and every consumer compares against the spelling it passed in, so the feed maps each key back.

### Refused: a directory safety net

The directory watch caught one thing the file watch cannot: a file nothing names yet. The chapter behind a broken `@include` is in no read-set — the read failed — so creating it rebuilds nothing until another watched file changes. Keeping a recursive directory watch beside the feed for that one case would keep the machinery this round deletes, and a new core outlet listing failed reads would be bookkeeping the next step makes unnecessary. **Accepted, and recorded here as the regression it is.** Closed 2026-09-24 in the CLI by [The render reads through the session](the-render-reads-through-the-session.md): the render reads through a Provenance pass, a failed read is a watched miss, and creating the chapter rebuilds. Closed the same day in the editing server (DESIGN.md 53): the tab's render reads through a pass the server holds, and a failed render ends it too.

## Consequences

- `chokidar` is gone, and with it `CHOKIDAR_USEPOLLING`, which `docker/Dockerfile` set because inotify does not cross Docker Desktop's bind mounts. Provenance's Node host uses `fs.watch` and has no polling mode, so in the container a file changed from the HOST side of the mount may go unnoticed; the editing server's own writes happen inside the container and are seen. Unmeasured on Docker Desktop; the image's environment line is removed rather than left to promise something.
- Provenance is a registry dependency on the same terms as Cascata: exact pin, GitHub Packages, the same `read:packages` token ([the repos chapter](https://github.com/egildo/beltype/blob/42b348b547d269a217a7f193042fe216386a4650/docs/repos.md)). The tap needs a second verified `resource` for its tarball. `postcss` and `parse5` install with it and are never loaded.
- The editing tools' conflict door and the feed now disagree about identical bytes. The tab's conflict test is an mtime and it adopted a new one from the `changed` that followed any rewrite; an identical rewrite is no signal now, so the next save of an edit meets a 409 and a merge over byte-identical disk. Measured, and recorded in DESIGN.md 51; answered the next day by comparing the base by content, the tab sending the SHA-256 of the text its draft was measured against and the server hashing the disk at PUT time — DESIGN.md 52.
- A path added while its file was missing and behind a symlink may outlive its removal from the set (Provenance canonicalizes again on `removeRoot` and misses): one harmless extra watch until the feed closes.

**The next step was BelType's hosts reading THROUGH the session, with Provenance 0.2.0's read passes** — taken for the CLI and then the tab's host on 2026-09-24 ([The render reads through the session](the-render-reads-through-the-session.md)). `session.read(label)` returns a pass whose `host` has Cascata's shape and records every read with the version of the bytes it handed out, AND every location it found nothing at; `pass.end()` makes those the label's roots, replacing the previous render's. When the CLI's and the tab's hosts read through a pass, the read-set stops being bookkeeping BelType keeps beside the render — the pass's manifest IS the read-set — and a failed read is a watched probe, so the missing chapter's appearance is a change and the regression above closes without a directory in sight. (0.1.0's `session.host`, which added a root only on a successful read, is gone.)
