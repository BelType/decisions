# The alias is the mount

**Status: Decided 2026-09-03.** Part of the BelType-on-Cascata round, beside [the URL root is the venue](the-url-root-is-the-venue.md), which is the other half of the same table.

## Context

BelType had a **mount law**, and it had grown five owners. `resolveMount`/`unionMounts`/`mountRoots` in `common/src/paths.js` held the algebra; `anchorConfig` minted two origins of its own; `plugins/assets.js` anchored the entry document's refs; `include.js`'s `mountFor` anchored an included chapter's. Two of those five minted labels **positionally**: an out-of-tree included chapter got `/_inc/N`, a mold's assets got `/_spec/N`, and `N` counted up per render in whatever order that render happened to walk the tree. The venue itself had a `/_venue` of its own. Nobody wrote any of those labels, and nothing outside one render could interpret them.

That is a rule about **a generation**, not about a configuration, and it cost exactly what a rule about a generation costs. Because label 3 meant one chapter's images this render and possibly a different chapter's the next, a server holding the previous render's mount table beside the new render's HTML answered another chapter's image with HTTP 200 and no error anywhere. The whole atomicity apparatus around the publication existed to close that hole: `mounts` rode the generation, rode `GenerationState`, rode the editing tools' publication POST, and every consumer had to swap the document and the table in one assignment or be silently wrong. The tab restated the mount law a second time in `urlPathFor` for want of a shared one, and the CLI's watcher had an `addMounts` feed to keep chokidar looking at directories no author had named.

## Decision

**`rewrites` is one author-named table, and a rewrite's name IS the URL prefix its target is served under.** `"@house": ../shared` means `@house/theme.css` resolves on disk under `../shared` and is served at `/@house/theme.css` — in a config value and in the markdown body alike, one name for both spaces. An alias written with a leading slash (`/seeds`) serves at `/seeds/`, which is how a venue whose built site already uses a path keeps it.

**Nothing is minted.** `/_inc/N`, `/_spec/N` and `/_venue` are gone, and no label is generated positionally or otherwise, which is what makes the table a fact about the **configuration** rather than about one render. That is the whole of what the deletion bought, and it is larger than the deletion: `mounts` leaves the generation, leaves `GenerationState`, leaves the publication POST; `addMounts` goes; the tab's second copy of the law becomes one call to core's own `urlForPath` against the config it already fetches. A stale publication can no longer answer another chapter's image with a 200, because a publication no longer says anything at all about what a URL means.

**A ref that lands outside the URL root under no alias is REFUSED, naming `rewrites`.** The old law's answer was to mint a label the author never wrote and quietly publish a directory they had not offered; the new one is an error that names the key and the move. Out-of-tree assets are *named*, never searched — a search would silently take the first match, and naming a folder as a source of configuration was never consent to publish its drafts.

**The algebra has one owner: the Linker.** `urlFor` anchors a ref against the directory of the file that declared it and expresses it against the root or an alias; `sourceFor` and `urlForPath` walk the same table backwards for the dev server, the editing tools' server and the closure; `rewriteRoots` lists the directories the table reaches, which is what the servers allow-list (and what the watchers watched, until [Provenance watches the files](provenance-watches-the-files.md) made the watch set files). Longest containing alias wins, so a table naming a directory and its subdirectory is order-independent. It is pure string algebra with no `fs`, which is what the browser-runnable core needs it to stay.

## Consequences

`common/src/paths.js` loses the mount rule entire — it was the shared half of a law that no longer has two halves. `plugins/assets.js` was **absorbed rather than ported**: its mdast pass anchored the entry document alone, correct only while `/` meant the entry's own directory, and [the URL root is the venue](the-url-root-is-the-venue.md) made the entry need anchoring exactly like any chapter, so `include.js`'s `rebaseAssets` stopped skipping it and the second pass went with the exception. `mountPaths` — the author-facing key the old law offered — joins `cascade.js`'s refusal list with the move written into its message, because a venue that keeps writing it deserves the sentence rather than silence. Two documents in this repository needed an alias to keep building and both are the law working rather than around it: the manual's cross-references to the repository's decision records had been emitted as `../../../docs/…`, which a browser collapses and 404s, and they resolve for the first time as `@decisions/…`. The mount tests moved to `test/linker.test.js` with their scars intact — the trailing slash, the escape refusal, the longest match, the path boundary — every one of which was a real defect and none of which was ever about mounts as such.
