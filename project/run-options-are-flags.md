# Run options are flags

**Status: Decided 2026-09-02.** Follows [cascata-owns-the-cascade](cascata-owns-the-cascade.md); part of the BelType-on-Cascata round.

## Context

`port`, `target`, `watch`, `open`, `engine`, `out`, `pdf` were `config-schema.js`'s `operator` territory: keys a venue could offer as a standing default and only the CLI could override, enforced by `checkTerritory` as a build-failing error because — `CLAUDE.md`'s own words — a key spoken where it cannot be read used to be silently inert (frontmatter `engine:`), and a PDF cannot be re-checked after it ships. [Cascata owns the cascade](cascata-owns-the-cascade.md) deletes that whole apparatus; the question this entry answers is where run behaviour lives once nothing enforces territory by rung and by key any more.

## Decision

**Run options leave the cascade entirely and become CLI parameters, scriptable by the operator. There is no `run:` block anywhere, in a schema or in frontmatter.** `port`, `target`, `watch`, `open`, `engine`, `out`, `pdf` are `beltype`'s own flags and nothing else's business; a venue schema has no vocabulary for them because BelType's root schema never declares them as keys at all — not sealed against, simply never spoken of, the same way `config-schema.js` never gave `port` a `document` territory in the first place.

**What survives of the territory apparatus is one refusal list, checked once over the projected value**, after Cascata has resolved the whole pedigree: `spec`, `schema`, `requires`, `cover`, `mountPaths`, `port`, `target`, `watch`, `open`, `engine`, `run`. (This entry first listed `plugins` and `directives.<x>.render` here too; a ruling on 2026-09-03 kept the render mechanism — `packages/essay/book`'s `embed-proof`, `embed-file` and `embed-corpus` compute HTML from the repository at build time and no `{ tag, className }` expresses them — so both came off the list, and the sentence is corrected here rather than left to contradict the code. `plugins` came off with it: a `plugins:` key is an ordinary document key now, declared by the root schema and legal at any rung, which is a widening the old `venue` territory used to forbid.) The reason a list is enough where a territory matrix was not is that the two are answering different-sized problems. The old matrix had to adjudicate every key against every source — document keys in the wrong config file, operator keys in a spec, `plugins` outside the venue — because nothing else did that job. Most of that job now belongs to the schema itself: a root schema that never declares `port` as a key, sealed `closed` where it chooses, refuses a stray `port:` in a venue the same way any undeclared key under a closed seal refuses — Cascata's own governance, not a table BelType maintains.

**The one thing schema governance structurally cannot do is close frontmatter's root**, and that is the scar this list exists to keep shut. Frontmatter is a shared surface — `date:`, and whatever other tool's word a document carries beside BelType's own, has to ride through unread and untouched, which is exactly why `configuration.md`'s old model kept frontmatter silent for unknown words rather than erroring on them. Sealing the root schema to police run options would seal it against every third party's word too; there is no way to close the door only against BelType's own reserved names while leaving it open to `date:`. So the root schema stays unsealed, and the refusal list is precisely the door that closes only the names it names — narrow by construction, because these are BelType's own reserved run-behaviour words and nobody else needs `--port`'s semantics from a Markdown file's frontmatter. This is the old scar exactly: a `port:` or `engine:` typed into frontmatter used to merge into the resolved config and never be read by anything, which is what `CLAUDE.md` calls silently inert and names as the reason territory became an error rather than a warning in the first place. The list stops that recurrence at the one seam schema governance cannot reach; everywhere else, the schema itself already does the job the old matrix did by hand.

## Consequences

`packages/cli/src/args.js`'s own docstring — the CLI is the operator's live word, it has the final say on run-behavior keys, and deliberately carries no document keys — needed no rewrite in spirit, only in mechanism: the enforcement moves from `config-schema.js`'s `operator` territory cell to this one list, checked at one seam instead of at every rung's load. A future run option joins the list by hand, the same cost the old manifest carried for a new operator key; the difference is that nearly every entry needed no new cell in a schema anyone authors, because a schema that never speaks a word cannot leak it. `~/.config/beltype/config.yaml`'s retirement — [the MVP cut](the-mvp-cut.md) — follows from this directly: every key that rung held was operator territory, and operator territory is now the CLI's whole story.
