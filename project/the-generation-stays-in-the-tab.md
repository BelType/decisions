# The generation stays in the tab

**Status: Decided 2026-09-04, Executed 2026-09-04.** Its *one engine* clause was superseded by [Paged.js returns in its own window](paged-js-returns-in-its-own-window.md). Its tree's `readSet` and `resources`, the write door's membership and the tab's two lists were superseded by [The render reads through the session](the-render-reads-through-the-session.md) (2026-09-24): the server now reads every render through Provenance read passes, and what they served is what it watches, what it admits writes against, and what it hands the tab back as its lists. The rest stands.

## Context

`packages/editing-tools` was built in nine rounds over two days (2026-08-27/28) and then rode the Cascata round. It works, and it carries the scaffolding of every round it grew through: three engines, one of them demoted with its own refresh button, a secondary side-by-side pane, per-engine publication slots on the server, three WebSocket signals, a server that runs the cascade beside a tab that runs the cascade, a preview route with a dressed and an undressed variant, and a Cicero pane exempt from the preview environment on a measurement nobody had acted on. The first sentence of `src/server.js` — *it holds the filesystem and nothing else* — was not true: the server held a resolved config, three generations of HTML, the closure, the spine and the write-set.

This is an MVP cut of the package, on the pattern of [the MVP cut](the-mvp-cut.md): keep what tests the claim, delete what does not. The claim is **the whole BelType pipeline runs live in a browser tab — schema and markdown in, a paginated document out — with the preview's style environment being the closure, materialized.** Cicero is the one engine kept, because it is the one that paginates in a tab and the one the constructed-stylesheet theory had never been tested against. Not live pagination — every edit still reloads the preview document — and still filesystem-based: the server is where the files are.

## Decision

**The generation never leaves the tab, and the server learns three things instead of holding one.**

**The venue is probed, and that is the whole of what the server resolves.** At start it runs core's `findVenue` over its node host — which file is the venue is meaning, and a host supplies bytes, so Article VI draws the line exactly there — and answers `beltype:document`'s location through `createNodeHost().locate`. It never calls `resolveConfig`. The probe's WHOLE answer travels to the tab (`{ dir, schema }`, on `GET /_beltype/edit/session` beside `target`, `rootDir`, `cwd`, `homedir`, `schemaLocations` and the engine list), because a tab handed the directory alone would run a cascade that never reads the venue's own file. `session` replaces `config`: host facts only, and no resolved configuration on the wire at all.

**The publication becomes the tree.** `POST /_beltype/edit/tree`, token-guarded, carrying `{ rewrites, readSet, resources, problems, ms }` — the alias table the server resolves URLs through, the read-set it watches and admits writes against, the text-kind resources that are the other half of that door, the closure's problems for the terminal, and the compile clock. The document is not among them. `build`, `preview`, `files` and `config` are gone as routes, and `GenerationState` has one consumer left, the CLI.

**The URL root is pinned to the probed venue; only `rewrites` comes off the wire.** The tab could post any root. An author can already reach any directory by naming it in `rewrites`, so pinning the root removes a question rather than a capability.

**The preview document is the first entry of the working generation.** The tab undresses the HTML itself — `undressHtml` is pure and moved to `assets/dressing.js` with the composition — and publishes it to the Service Worker's cache under `/_beltype/edit/preview`, through the same `draft` message the CSS road already used, because that is what it is: the preview URL's bytes, held by the origin. The cache is renamed `beltype-working`, which is what it holds. The frame therefore loads a real URL at the origin: anchors scroll, module scripts run, and the never-`srcdoc` rule holds with no server-side document — undressing used to happen server-side for exactly that reason, and the reason is gone. The Service Worker is a **precondition** now rather than a convenience: `init()` waits for a controller before the first compile and refuses in a banner where there is none, because a tab with no worker has no preview at all and an empty frame explains nothing. The message channel gained an ack, since the frame's reload would otherwise race its own cache write.

**Refused: `postMessage` plus `document.write`.** A new mechanism with parser-inserted-script semantics to measure, where the Service Worker road is already measured and already live.

**One change signal.** The watcher batches every path that moved inside its 300 ms window and the server broadcasts `changed { paths }` — with paths, which it never carried. The tab classifies, holding the two lists that already discriminate: a `readSet` member recompiles; a text-kind resource reloads the frame. **`config-changed` is gone**, and its absence is a consequence of [cascata owns the cascade](cascata-owns-the-cascade.md) rather than a simplification: the cascade re-runs per render, in the tab, so a venue's schema is an ordinary read-set member and needs no signal of its own. `reload` is gone with the reload client it addressed.

**The reload client needs a port.** `core/src/shell.js` omits it when `config.port` is absent — one added condition beside `export` and `print`, behind `omitReload()`. The client's only act is to open a socket at the `data-port` it carries, so a host that names none would emit a tag pointed at `undefined`. This host names none; the CLI's dev server always names one and is byte-for-byte unaffected.

**The host drives the engine.** The tab composes the engine as the seam's object with `bootstrapJs` replaced by one statement — `window.parent.postMessage({ type: 'beltype:ready' }, location.origin)` — which the shell splices after its own client stages, so `ready` means the document has stopped changing. The app then dresses the frame from the generation it was published from, re-applies dirty CSS drafts, and calls `frame.contentWindow.__beltypeCicero.run()` directly, reading `{ pages, ms }` off the promise for the status line; a rejection becomes `cicero refused` and the engine's own message in the banner, because Cicero's refusals are load-bearing text and must reach the operator. This replaces both a 10 s poll of a global and a `load`-based dressing lifecycle — `load` does not wait for a module bootstrap's async work, so it was never the right moment for a paginating engine.

**Refused: a three-message protocol** (`ready`/`run`/`done`). A same-origin call is the house's existing pattern here, and a serialized channel buys nothing until the engine leaves the realm, which is a parked horizon.

**The write door collapses to two locks.** A path is writable when it is a `readSet` member or the source of a text-kind resource, AND it sits inside `rootDir` or inside the venue directory. The exact-membership door for config files is retired: a venue's own config sits inside the venue directory by construction, so containment expresses it and no second list has to be kept in step. BelType's own root schema sits outside both roots and stays readable and unwritable — by geography now rather than by an exception.

**One engine, and its pane is dressed.** `site` and `pagedjs` leave this package — the engine table is `['cicero']` on both sides, `@egildo/beltype-engine-site` leaves `package.json`, and the import map keeps one engine prefix. The engines stay in BelType; they left this tool, and would return through the same seam one per round, each answering the preview environment's dressing question for itself. Cicero's pane is dressed because its own round answered the exemption at the source (engine-cicero's *the capture reads adopted sheets*), rather than the tool working around it.

**Refused: keeping the in-place CSS draft.** P7's `replaceSync`-in-place road was the site engine's payoff — a sheet swapped with no reload, no scroll lost. Under a paging engine it changes what is painted and cannot re-paginate, because `run()` adopts the document destructively and is not re-entrant, so the pane would show new colours on old cuts: a preview that lies. A CSS draft publishes to the worker and reloads the frame; `reapplyDrafts` on `ready` keeps a freshly dressed pane draft-true.

## Consequences

`packages/editing-tools/DESIGN.md` gains a dated section, and the propositions this displaces are marked superseded in place: 6, 10, 14, 17, 21, 22, 23, 32, 33, 34, 35, and the watcher item on the open list. `docs/reference.md`'s protocol section is rewritten around `session` and `tree`; `repos.md` loses the `editing-tools → engine-site` edge; `architecture.md` gains the cut's own paragraph beside the five things of 2026-08-28.

What the round costs, stated rather than absorbed: `site` and `pagedjs` lose their only automated browser-import proof. They keep `test/engine-seams.test.js`'s plain-node import, `test/contracts.test.js`'s bootstrap-parse pin, and — for `pagedjs` — `beltype build --pdf` end to end. That is the price of the cut, and it is named in the suite that used to carry the proof.

What is deliberately not this round: live pagination (a `run()` that re-enters); the belt in a dedicated Worker (DESIGN.md proposition 29); the standalone backing; `site` and `pagedjs` returning; fonts constructed (proposition 38). And one pre-existing limit stays: an `$adopts` outside every reachable root is unreadable from the tab, and the tab's cascade refuses it honestly.
